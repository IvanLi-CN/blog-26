# 内容向量随内容删除 主题历史

> 这里记录主题局部生命周期、替换、兼容性与必要背景；完整 ADR 取舍保留在 `docs/adr/`。

## Lifecycle / Compatibility

- 新主题。前序状态只有一次 `innerJoin` 修复（PR #524），它消除了误报但未阻止存储增长；本主题接管存储侧。
- 与 `docs/adr/0045-embedding-ownership-foreign-key.md` 绑定，ADR 记录为何选外键而非触发器与计划任务。

## Background

孤儿向量是长期结构性泄漏而非事故：`post_embeddings` 无引用约束，多数删除路径只删 `posts`。修复统计口径时确认已有大量「键无法直接对应 `posts.id`」的行，且仍在产生。

**后续更正**：最初的口径把两类问题混在了一起。逐条核对后，只有一部分是真孤儿，另一部分是早期以 `/` 前缀写入的遗留键，其对象大多仍存在；遗留键里多数是被标准键覆盖的重复行，少数是唯一覆盖行。据此修改迁移：先归一化再判孤儿，并先除去重复再归一化，否则会误删唯一覆盖行，或撞唯一索引。

曾评估三条替代路线，均放弃：

- 计划任务方案，包括新增 `weeklyAt` 调度类型、`humanSchedule` 渲染与面板入口。因缺少可靠的过期判定字段、且与现行删除路径并存会产生两套真相而放弃。
- SQLite `AFTER DELETE` 触发器方案。因约束绑定数据库类型、删除后无任何应用层信号可记日志、且只覆盖显式挂上的删除动作而放弃，改为声明式外键。
- 「按裸 `post_id` 判孤儿」的简化迁移。初版即如此，实测会静默删除全部遗留键行，其中包含唯一覆盖行；外键开启时同一批行会让重建的 `INSERT` 直接失败。改为按归一化键清孤儿、去重、再归一化的三步。
