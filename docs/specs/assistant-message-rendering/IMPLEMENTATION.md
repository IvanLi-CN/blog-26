## Verification Commands

文档交接执行 topic Spec 合同检查、变更空白检查和新增链接目标检查；这些结果只证明文档结构与引用可用。产品实施时复用现有 `bun run check`、相关组件/状态测试及正式路由 Web Demo E2E，按实际改动范围运行，不能把计划运行的命令写成已通过。

格式 fixtures、解析与组件断言已建立，覆盖角色分流、标准换行与转义、列表与脚注、代码、公式、内容策略和消息状态。代码、图片与生成状态具有独立 Story；聊天正文的样式总览用于组合核查格式边界与主题一致性。完整界面的多消息、资源请求和阅读位置仍需在集成后执行最终回归。

集成候选 `f75bf15f41721372a2cd2d32bf820129b5d5e2bc` 的 `bun test tests/components/KnowledgeAssistant.test.tsx tests/components/ClippingDetail.test.tsx` 为 18 项通过。真实 DOM 用例检查当前轮 partial 与终态去重、共同前缀不吞新回答、代码主动折叠跨终态保持，以及历史阅读位置与返回尾部后的跟随。`ChatPanel` 使用同一消息行数组维持 React 节点身份；同一 key 分布在两个兄弟 children 数组不能作为状态连续性的证明。

该候选的独立 Web Demo 使用 `WEB_DEMO_DATA_DIR=dev-data/amr-integration-web-demo` 和独立构建输出执行 `bun run web-demo:build`，三个产物均成功。手工验证仅使用 mock 身份、固定回答及正式 `/chat` 路由，已观察用户输入中的星号与换行保留为字面文本，助手正文出现三个粗体列表项且来源仍在正文边界之外。页面截图不替代图片请求、生成提交次数或停止与恢复的端到端断言。

集成审查发现导入主线的发送按钮、输入框拖动柄及平板导航未达到共享响应式触控合同。修正统一以 44px 为触控命中区域下限，并为拖动柄保留不覆盖输入区域的间距；1024px 以上细指针环境的发送按钮与拖动柄分别采用 36px 和 32px。18 项组件测试及 `check` 已再次通过，修正后的页面布局与证据仍需复验。

## Remaining Gaps

尚需完成集成子 PR 验收及最终桌面/移动端回归。公开站与 Console 可达剪藏入口都必须覆盖；单个组件测试不能替代这些入口的端到端验证。[证据矩阵](./CAPABILITY-MATRIX.md) 保留审计基线观察，最终回归需逐项收敛其中的验收责任，不能将基线缺陷直接当作当前结论。

既有助手 E2E 在集成修正前的候选上仍有粗体与列表的严格多匹配失败：单条回答有三个 `strong`，且系统来源也有 `ul`；后续任务必须将断言限定至 `[data-message-body]` 并检验实际内容，不能删除或弱化覆盖。早期仅公开站 SSR 的验证环境未挂载 `/admin`，补齐生成的管理端 SPA 挂载后，原管理端入口用例已原样通过；该环境修复不等于全部 E2E 已通过。最终候选仍需重新运行适用完整套件。

当前生成侧不因本主题新增存储字段、编号映射、SSE 协议或迁移。产品验证涉及真实模型、真实私人数据、截图或远端动作时，仍遵循相应授权边界。
