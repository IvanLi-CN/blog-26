# 助手消息渲染实现状态

规范以 [SPEC.md](./SPEC.md) 为准。本文明确区分既有基础、源码证据和尚未执行的验收。

## Current Status

- Implementation: in progress。格式审计、代码、图片和消息状态基础已分任务实现；聊天 Markdown 入口已完成统一视觉与组件验收，完整界面集成和最终回归尚未完成。
- Lifecycle: active。
- Baseline: `cae60a01576256da1849e5e4898232d952bd6544`。该基线已经为统一助手接入共享 MarkdownRenderer，但不满足本主题全部内容策略与交互合同。
- Evidence: 已执行组件单测和受控 Storybook 验证；统一样式的定向测试、构建与九个浏览器场景已通过，浅深色组件总览已确认。组件证据不代表完整界面、真实模型或部署验收通过。

## Verification Commands

文档交接执行 topic Spec 合同检查、变更空白检查和新增链接目标检查；这些结果只证明文档结构与引用可用。产品实施时复用现有 `bun run check`、相关组件/状态测试及正式路由 Web Demo E2E，按实际改动范围运行，不能把计划运行的命令写成已通过。

格式 fixtures、解析与组件断言已建立，覆盖角色分流、标准换行与转义、列表与脚注、代码、公式、内容策略和消息状态。代码、图片与生成状态具有独立 Story；聊天正文的样式总览用于组合核查格式边界与主题一致性。完整界面的多消息、资源请求和阅读位置仍需在集成后执行最终回归。

## Remaining Gaps

尚需完成正式界面集成及最终桌面/移动端回归。公开站与 Console 可达剪藏入口都必须覆盖；单个组件测试不能替代这些入口的端到端验证。[证据矩阵](./CAPABILITY-MATRIX.md) 用于逐项收敛剩余能力与验证缺口。

当前生成侧不因本主题新增存储字段、编号映射、SSE 协议或迁移。产品验证涉及真实模型、真实私人数据、截图或远端动作时，仍遵循相应授权边界。
