# 技术选型

本选型建议以现有锁定依赖、已确认格式范围和 [能力核验](./CAPABILITY-MATRIX.md) 为依据。以下组件边界与选项是实施设计，尚未作为产品代码实现；不以依赖名推断最终界面已经验收。

## 当前技术栈

对话运行于 Astro 页面中的 React 组件，公开阅读采用自有 Nature UI、Tailwind CSS 与本地基础控件。Markdown 解析器独立于 UI 控件库；shadcn/ui 或其他控件库不能替代正文解析。

| 层次 | 当前锁定版本 | 处理建议 |
| --- | --- | --- |
| 页面与组件 | Astro 7.3.4、React/React DOM 19.3.0、Tailwind CSS 4.3.3 | 保留当前页面外壳与设计系统 |
| Markdown | react-markdown 10.1.0 | 保留，通过聊天专用策略组合 |
| GFM | remark-gfm 4.0.1 | 保留，覆盖任务列表、表格、删除线、自动链接与脚注 |
| 数学解析 | remark-math 6.0.0 | 保留，使用确认的美元分隔符合同 |
| 数学输出 | rehype-katex 7.0.1 | 保留；核对实际引擎和样式一致性 |
| 数学引擎/样式 | 根 KaTeX 0.18.9；rehype-katex 嵌套 KaTeX 0.16.47 | 已发现版本差异，先验证字体、布局和错误输出；必要时单独评估对齐，避免无证据全仓升级 |
| 代码高亮 | rehype-highlight 7.0.2、highlight.js 11.12.0 | 保留，未知语言普通代码回退 |
| HTML 净化 | rehype-sanitize 6.0.0 | 保留防御层；聊天不启用原始 HTML 转换 |
| 原始 HTML | rehype-raw 7.0.0 | 文章现有使用保留，聊天排除 |
| 图表 | Mermaid 12.0.0 | 不在聊天启用，不为本主题升级 |

版本来自本地 [package.json](../../../package.json) 与 [bun.lock](../../../bun.lock)，不表示这些是最新版本。

## 方案比较

| 方案 | 价值 | 成本与限制 | 本次结论 |
| --- | --- | --- | --- |
| 现有 react-markdown/unified，加聊天策略和消息内容组件 | 复用解析、高亮、数学与设计系统；修改已有属性丢失问题 | 需要自行补齐流式暂态、媒体边界、属性转发及回归 | 推荐；与当前约 650ms 完整快照输入匹配 |
| Streamdown 作为独立渲染器 | 官方定位支持流式和未终结 Markdown，具有代码、数学等扩展 | 需要验证未闭合语法修复是否改变原文、组件与样式适配、安全及媒体默认值、构建体积和依赖兼容；尚无本项目测量 | 保留为有证据瓶颈时的候选，不在首期迁移 |
| 更换为其他 Markdown 解析内核 | 可定制底层解析 | 仍需重做 React 元素、属性、公式、媒体与来源边界；没有已确认需求要求换内核 | 不选 |
| 引入完整聊天 UI/状态框架 | 可提供消息组合与交互模板 | 与已实现的私人对话、轮询恢复、额度、剪藏上下文和 Nature UI 重叠；迁移范围大于当前格式问题 | 不选 |

保留现有内核是基于迁移成本与当前缺口位置的工程判断，不是已证明的性能优势。Streamdown 的未闭合语法能力来自其官方说明；本项目尚未做比较基准，不写入更快或更小的结论。[react-markdown 官方说明](https://github.com/remarkjs/react-markdown)、[Streamdown 官方说明](https://github.com/vercel/streamdown)。

## 组合规则

1. 聊天输入直接进入标准解析链，不执行 `cleanMarkdownContent` 的全局文章修复。
2. 使用 remark-math 与 remark-gfm。脚注本就属于 remark-gfm 处理范围，无须为了插件名另加一套脚注解析。[GFM 官方说明](https://github.com/remarkjs/remark-gfm)。
3. 原始 HTML 节点按字面文本呈现，不启用 rehype-raw；后续插件仍需经过明确的净化与 URL 规则。react-markdown 的默认安全性会受到插件和自定义组件影响，不能作为整个应用已安全的证明。[HTML 与安全说明](https://github.com/remarkjs/react-markdown#appendix-a-html-in-markdown)。
4. 允许公式插件产生所需受控标记，禁止 KaTeX 的信任扩展引入 URL 或 HTML 能力。净化与公式输出顺序以项目锁定版本的 DOM 回归确认，不能无条件把默认 sanitizer 放到末尾导致公式失效。[数学插件说明](https://github.com/remarkjs/remark-math)。
5. 通过 AST/块级节点区分代码块与行内代码；语言只用于选择高亮，不能决定块级身份。图片分类在任何真实资源请求之前完成。
6. 共享只包含无内容信任假设的工具、组件和安全属性集合。文章的原始 HTML、媒体、清洗与折叠默认值由原主题继续拥有。

## 性能与扩展条件

先记录固定短文、长回答、长代码、宽表格和数学样本的解析/提交时间与更新次数，连同环境、样本大小和服务端快照间隔保存。保持相同消息 ID 与稳定参数，未变化消息跳过处理；终态正文优先立即提交。未证明有额外高频输入前不叠加固定延迟节流，不引入传输协议迁移或虚拟列表。

只有当前方案无法满足实测的内容更新和交互需求，且明确比较安全、样式、构建与维护成本后，才重新评估流式专用依赖。任何新增依赖或版本对齐都应有针对当前缺口的理由和回归范围。
