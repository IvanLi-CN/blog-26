## Implementation Coverage

- `getMemoPresentation` shares the clipping label, owner-selected Tabler scissors icon, and reading-tag projection across public/live Memo lists, timeline entries, detail headers, and preview. `MemoTypeBadge` supplies the shared detail header. Memo lists use their existing type icon without adding a clipping badge beside date or visibility metadata. Scissors are registered locally with the existing 24×24 viewbox and 2-unit outline so SSR and offline loading do not depend on the Iconify API. Stored and editor tags retain the clipping marker. Search responses supply an optional `isClipping` display hint for indexed Memos; result links keep Memo routes and the UI provides separate clipping counts/filtering.
- `src/lib/memo-clipping.ts` recognizes only authored tags and the first eligible input line, preserving the author draft separately from the reading projection. It accepts Milkdown's escaped literal `\#剪藏` and omits a repeated body target when the saved link-only title supplies that same target.
- `src/server/clipping/` owns extraction, private artifacts, lifecycle reconciliation, previous-success fallback, creator authorization, and the application-owned Pi facade. Pi AI, Chord, and Pi Durable are pinned to `1.0.2`.
- The Bun SQLite adapter passes Pi's storage conformance suite and enforces a single owner with lease/epoch fencing. Durable input, tool execution, conversation reopen, and a real subprocess SIGKILL/restart are covered by automated tests.
- UI, REST/tRPC, MCP, and filesystem sync share recognition and reconciliation. Startup repairs indices from authored references and canonical manifests. Notes-only edits do not restart the workflow; target replacement separates conversations and fences stale results.
- Chat submission now binds the authored memo, clipping revision, target URL, and current conversation under the same mutation queue used by reconciliation; it revalidates immediately before submission and before committing the answer, so a target change cannot receive a stale user message. MCP memo updates carry the authenticated actor into a newly recognized clipping reference, preserving creator-only discussion access when an ordinary Memo becomes a clipping.
- The extractor performs DNS/IP checks on every redirect, pins the connection address, limits redirects/time/decoded bytes, and never executes page scripts or loads child resources. Markdown retains headings, tables, links, and literal code.
- Summary is committed before translation. A reprocess keeps the prior `currentVersionId` until the new translation is complete, so a failed or partial translation continues to project the last successful source/summary/translation set while exposing the failure state. Translation segments and progress persist separately; failed reprocessing retains the last successful set of materials. Pi's persisted retry policy allows three transient model retries; provider-layer retries are disabled to avoid multiplying the budget. Fetch retries are independently bounded to three.
- Public reading, lists, timeline, feed, and snapshots use a composed reading projection. Public responses omit creator proofs, conversations, runtime events, and diagnostics. Private visibility is checked against the authored file as well as the index. Managed standalone article exports are removed when no longer public.
- `ClippingDetail` separates the left column into a Memo card (heading, remarks, summary, processing status, and actions) and a captured-article card (language controls and source/translation Markdown) with a 24px vertical gap. Both are siblings in an unframed stack; the sticky discussion card remains alongside that stack with its composer. Authorized views at 1024px use the wide content container with a 24px column gap and 320–360px discussion column; visitors and ordinary Memos retain the single-column reading measure. Narrower views use Vaul/Radix bottom sheets with retained draft/scroll and focus restoration. Console, static Memo rendering, and admin preview use the same card ownership. Cards remain stationary on hover/focus, and discussion prose uses a compact reading rhythm.

## Storage and Deployment

- The application Markdown and managed clipping version files are canonical business content. Application SQLite tables `memo_clippings` and `memo_clipping_versions` are rebuildable indices; migration `0011_memo_clipping.sql` adds them without changing ordinary memo rows.
- `PI_DURABLE_DB_PATH` defaults to `pi-durable.sqlite` beside `DB_PATH`; `CLIPPING_CONTENT_BASE_PATH` defaults to the sibling `clippings/` directory. Both must be on persistent storage outside `LOCAL_CONTENT_BASE_PATH`; the Pi database must differ from the application database.
- Each clipping directory contains `manifest.json`, version directories with `source.md`, `summary.md`, `translation.md`, and numbered translation segments. Atomic writes and target revisions prevent partial publication and stale task writes.
- `identity.key` is a private 0600 HMAC key in the clipping storage root. Trusted create paths sign `[memoId, clippingId, creatorId]`; copied or edited references cannot forge the creator. Unverified filesystem imports allow administrator-only discussion.
- Back up authored Markdown, the entire managed clipping directory **including `identity.key`**, the application database, and the Pi database together while the processor is stopped. Restoring only the index cannot recover conversation state. Restore the same directories/configuration before starting the sole runtime owner.
- If the configured content directory is not created yet, runtime startup leaves the processor inactive so legacy gateway/port-only bootstrapping can complete; create the configured content directory and restart to enable processing. Ownership conflicts, unsafe paths, and permission errors still fail closed.
- Production `start-console` and development `start-gateway` own runtime startup/shutdown. Page rendering, sync-only scripts, and build/export processes never start a Pi owner. Heartbeat is 10 seconds; lease is 30 seconds. A second live owner fails startup; after a crash wait for lease expiry before restarting.
- Default clipping concurrency is two. Existing LLM chat settings supply the provider, model, endpoint, and secret. Secrets are resolved dynamically and are not stored in Pi conversation configuration.
- `CLIPPING_PROCESSOR_ENABLED=false` is the rollback switch. It stops accepting processing/actions while preserving authored input and previously saved reading materials. No automatic publication or deployment is performed.

## Operations and Troubleshooting

- Invalid first-line links save successfully and show a correction prompt. Fix the authored link/tag or use reprocess after correcting model configuration.
- When `.env.local` and inherited shell LLM variables disagree, the inherited variables take precedence. Restart with the intended provider configuration; do not rewrite author input or generated artifacts to repair authentication.
- Unsupported HTML, private destinations, redirect loops, timeouts, oversize payloads, or insufficient extraction produce explicit failure/partial states. Login, CAPTCHA, PDF/OCR, and JavaScript-only pages are unsupported.
- Processing versions are internal checkpoints and fallback material only. There is no version-history interface, past-conversation browser, or manual restore endpoint. Failed reprocessing preserves the previous successful source/summary/translation set and identifies its true source.
- SSE delivers persistent snapshots and partial output; reconnect reads the snapshot again. Server identity and permissions are checked for every private event. Full articles are fetched only for detail, not list payloads.
- The opt-in `scripts/clipping-empirical.ts` runner uses a private acceptance directory. `--extract-only` saves a private source artifact without calling a model; `--probe` checks the actual page and provider; the full run requires `CANDIDATE_SHA` and records the source hash, segment coverage, configured model, and cited answer. Do not publish its private working database or credentials.

- Ordinary implementation PR merges no longer publish a product automatically under the manual-release contract. This feature does not modify `VERSION` or initiate the manual release workflow. Current API/state impact evidence is recorded in `docs/version-impact/memo-clipping.json`; superseded overlapping file coverage is removed from the preceding manual-release assessment.
