# Style Playbook集成

## Context and Scope

本主题定义博客原生展示 Style Playbook、静态站独立发布，以及动态服务从 GitHub 读取并采用 Playbook 快照的长期契约。

范围包括上游公开目录中的 Topic、项目实践快照和 Policy Skill、它们的正文、公开资源与关系、博客导航及统一搜索、静态站发布、动态服务的 GitHub 内容读取、数据库完整快照、内容同步管理、管理员浏览，以及失败处理。上游知识内容的管理与写入、私有内容和未进入公开目录的分组/读写 Skill 主文档由上游负责；文章与 Memo 的实时读取边界由既有主题负责。动态同步不读取静态站、不承担静态站发布或生产回滚；静态站发布合同与动态内容提供方合同彼此独立。

统一搜索以搜索内容对象为读者的比较与选择单位。整页、章节、命令或资源文件的多个命中必须汇入同一个内容搜索结果，避免长文占据多个顶层位置并挤掉其他内容；该聚合语义共同适用于文章、Memo、Topic、项目实践快照和 Policy Skill。跨来源共同排名、全局容量、查询语法与接口由 [搜索主题](../search-relevance/SPEC.md) 定义；本主题拥有 Playbook 的公开内容、版本、位置和同步管理边界，不引入全文转载去重、跨内容相似度合并或新的检索服务。

博客主导航与栏目标题均使用两字名称“执念”，项目集合与搜索类型显示为“项目实践”。

## Requirements

### REQ-PBI-001 — 原生阅读集合

博客必须继承 [Nature UI 响应式契约](../nature-front-ui/SPEC.md#44-responsive-control-and-code-density)，复用自身布局、导航、阅读样式、目录、移动布局和深色主题，完整展示公开目录中的 Topic、项目实践快照和 Policy Skill。每个对象必须能从索引进入正文，保留关联与 section anchor；访客界面不展示采用的内容版本，版本身份用于数据一致性与发布追溯。Playbook身份与文章、Memo、博客标签和现有项目案例必须独立；Policy Skill 阅读或复制命令不得自动执行安装。入口分类选择器（“全部 / 主题 / 项目实践 / 规则”）的悬浮、焦点和触控反馈不得移动交互元素自身的命中框；视觉状态只能改变颜色、背景或阴影等不影响命中边界的属性，需要抬升时位移必须作用于不参与命中的内部视觉层，并保持每个入口至少 44px 的可用高度。公开静态页禁用 JavaScript 时必须仍有完整正文和导航，console 首次响应必须提供 SSR 正文。

桌面详情页的 Hero 必须横跨正文与目录两栏。目录必须位于正文旁的侧栏，复用主题原生卡片，标题采用辅助导航层级，并在顶部导航下方随滚动固定；目录宽度不得挤占正文的正常阅读空间，锚点跳转后的章节标题不得被顶栏遮住。640–1023px 的目录放在正文前，使用与正文一致的主题卡片底色、边框、圆角和阴影，不得直接落在环境背景上。小于 640px 的移动端目录直接放在正文前，复用全宽、平面的阅读承载层，不使用独立卡片、圆角、边框或阴影，并保留无 JavaScript 导航能力。目录必须呈现正文真实标题层级，保留标题原文及已有编号，不自动添加章节编号。正文前目录的主章节条目采用 32px 纵向步距，子标题使用缩进、辅助色与 24px 步距，每个主章节组之间留 4px 间距。移动端目录标题配合目录图标，子标题通过细分支线连接到所属章节；当前项采用文字强调与细下划线，避免整行填色呈现为菜单按钮。悬浮菜单使用独立的 36px 触控间距。启用 JavaScript 时，正文前目录、桌面目录与悬浮目录同步强调当前阅读标题及其父章节；展开悬浮目录时定位并聚焦当前条目。子标题锚点必须在静态 HTML 和 SSR 中可用，且与目录一一对应。目录区完全滑出屏幕顶部后，右下角出现纵向的“目录 / 回到顶部”按钮组，距屏幕边框至少 16px，并考虑安全区域。按钮组从屏幕顶部中间沿弧线进入，组本体轻微收稳；悬浮目录使用紧凑菜单样式，从按钮组向左上展开，宽度随内容适配，最小 200px、最大不超出视口边距，长目录可内部滚动。再次显示正文前的目录区时收起按钮组。浮层支持锚点跳转、关闭按钮、外部点击和 Escape，减少动态效果时使用短淡入淡出。

### REQ-PBI-002 — 公开数据边界

Policy Skill 的公开文本文件必须能在页面内直接查看，预览区由可关闭、可重新展开的文件树与文件窗口组成。资源区标题右侧提供放大显示按钮，启用 JavaScript 后将同一工作区放入铺满当前视口的模态阅读层，使用主题底色、平面边界及移动安全区边距；文件、阅读/源码模式与有效滚动位置继续保留。放大期间背景不可操作且锁定页面滚动，支持按钮与 Escape 退出并返回原按钮焦点，恢复页面位置与原尺寸；移动文件树开启时，Escape 优先收起文件树。无 JavaScript 时不显示放大按钮，原生文件阅读仍可用。公开资源位于正文之后的独立分区，自占一行。桌面端使用主题卡片，横跨正文与目录两栏，与详情 Hero 同宽；移动端复用全宽、平面的阅读承载层，贴合视口两边，内容按共享阅读边距内缩，不使用外层卡片圆角、边框或阴影。文件树、工具栏与文件窗口共用资源分区底色，不额外叠加明暗背景，仅通过细分隔线与选中状态区分。文件树保留真实相对目录和文件名，切换文件后保持目录展开状态；关闭文件树后窗口使用可用全宽。启用 JavaScript 时，浏览器使用具有上下限的稳定视口高度，切换长短文件、阅读/源码模式和文件树显隐不得改变整体高度。文件树、Markdown 阅读区和源码分别内部滚动，工具栏与预览方式固定在文件窗口顶部；阅读与源码滚动区支持键盘操作。移动端文件树使用预览区内的非模态浮层，不参与上下布局，不挤压预览空间；浮层使用主题底色和适度阴影，宽高限制在工作区内，文件列表独立滚动。浏览器地址栏变化不得引起工作区持续伸缩。禁用 JavaScript 时保留原生折叠项的自然文档高度。代码、配置与 Markdown 源码采用博客现有明暗主题语法高亮，未知文本格式显示原文。Markdown 提供受控阅读与源码切换。阅读模式识别文件开头完整的 YAML frontmatter，将文件头与正文分离，再按 `REQ-PBI-016` 筛选并呈现访客阅读信息；仅将正文交给 Markdown renderer，兼容 JSON 形式的 YAML 元数据、BOM 和 CRLF。错误或不支持的文件头不在阅读模式中回显原始内容，完整原文仍可通过源码与下载查看；不得执行自定义 YAML 标签。文件之间的相对链接只能映射到同一 Skill 已公开的文件；所有文件提供同版本匿名下载。移动端文件树默认收起，从窗口工具栏下方自然浮出；选择文件、点击浮层外部或按 Escape 后收起，关闭按钮与 Escape 将焦点返回工具栏，重新展开时聚焦当前文件。非模态浮层不锁定页面滚动或使用对话框焦点陷阱，减少动态效果偏好禁用动画；展开时仅滚动文件树以显示当前选择，保持页面阅读位置与预览高度。跨越 640px 工作区宽度时切换浮层与桌面侧栏；文件选择、目录折叠与预览方式等触控目标至少为 44px。静态 HTML 与 console SSR 必须包含文件内容，禁用 JavaScript 时仍能通过原生折叠项查看；页面内预览不得执行脚本、HTML 或 Mermaid。

公共页面、公共 JSON 与公共搜索只能消费上游经过可见性和内容检查的公共导出，必须排除目录私有项目、私有 Topic、内部字段、生成记录、管理数据及凭据。公共项目必须明确包含 `catalog_visibility: public` 与 `source_visibility: public|private`；来源私有项目在公共投影中只保留 `source: private`，不得输出私有 source URL。Topic 必须独立包含 `catalog_visibility`，权限不得从项目推导；`related_projects` 是 Blog 关系唯一真相源，正文中的旧前置链接不得参与构建。非公开整理知识只通过同一 Release 的补充包进入受保护的管理员读模型。缺失、非法、重复或互相矛盾的结构化字段一律拒绝；不得用原始仓库 Markdown 扫描或内部 API 绕过包合同。共享正文按原文复制，不执行 sanitizer、敏感词替换、标题改写或逐段重写；边界校验失败时直接拒绝。公共正文必须按现有受控 Markdown renderer 展示，不得执行包内脚本或 MDX。

补充包是公共包的 overlay，只包含公共包省略的目录私有项目、私有 Topic、关系边和 `private_source_metadata`，不重复公共正文或公共项目记录。Blog 接收端必须验证补充包与公共包的 source identity、manifest、归档根文件、记录关系和搜索路由；接收入口只接受受保护的同步令牌，并按来源身份原子替换暂存状态。缺失或不匹配的补充包只能使管理员 overlay 不可用，不能削弱公共 edition；公共版本切换失败时保留上一版公共与管理员读模型。管理员搜索和浏览可以看到合并后的完整目录，但补充包不得进入公共指针、静态页面、匿名 API 或公共搜索索引。

### REQ-PBI-003 — 静态站公开包身份

静态站自动发布可以采用非 draft、非 prerelease 的稳定 Release，并固定仓库身份、Release ID/tag、tag 解析后的源 commit 和包 digest。首次引导与补漏可枚举稳定 Release，按 SemVer 选择最高的就绪版本；选中后，构建必须固定该 Release 的身份并校验 manifest、tag commit 和包 digest。不得下载浮动的 `latest` URL，也不得以当前分支导出冒充旧 tag。该静态发布身份不作为动态服务的内容来源；动态服务遵循 [GitHub 内容源契约](./contracts/github-source.md)。

### REQ-PBI-004 — 静态站独立发布

博客内容 workflow 每小时检查一次上游稳定 Release；发布资产齐全且通过校验后，自动选择最高的就绪稳定 SemVer 并构建、部署公共静态站，同时按静态发布合同处理补充投影。静态站的调度、启停和回滚开关由静态发布合同定义，不得被动态 GitHub 内容提供方配置代替。博客使用已发布的稳定前端渲染器和明确身份的文章/Memo 公开快照；未经应用发布门禁的最新 `main` 不得自动作为静态渲染器。人工重试与上游通知继续复用静态发布合同，不能触发动态服务读取静态站。

### REQ-PBI-005 — 内容与应用发布分离

纯Playbook内容刷新必须独立于应用 SemVer、应用 GitHub Release 和 console 镜像构建。Playbook输入必须独立于依赖 console 的 posts/memos `public-snapshot.json`，Playbook构建不得反过来依赖 console 的Playbook缓存。普通前端代码发布必须保留当前采用的Playbook版本并检查兼容性；首次路由和缓存能力上线通过正常应用发布完成。

### REQ-PBI-006 — 静态发布与动态同步隔离

静态发布流程的内容更新、显式回滚与应用代码发布必须遵守其生产部署互斥边界，在途部署不得因新触发被中断。动态 GitHub 同步不加入该静态部署锁，不写入静态指针，也不因静态站部署状态改变内容快照。动态同步按来源 commit 和内容 hash 做幂等比较，不使用 SemVer 对 GitHub commit 排序；普通同步不得自动降级，受控回滚必须通过明确的来源配置或运维操作完成。所有重复任务、迟到结果和失效租约都不得覆盖较新的数据库采用结果。

### REQ-PBI-007 — 同批发布与版本资产

Playbook页面、目录、详情、搜索数据和当前指针必须来自同一次成功部署，记录上游版本、包 digest、博客渲染器 commit 与文章/Memo 快照身份。版本文件必须使用不可变缓存，当前指针必须使用短缓存或重新验证。部署必须保留尚可被上一批指针引用的版本文件，并保留原始发布包供回滚；不得假定替换整站后旧目录仍可访问。

### REQ-PBI-008 — console 读取 GitHub 并原子采用

console 必须从配置的 GitHub 仓库和 ref 解析一个 commit SHA，读取该 commit 上约定的完整公开导出，校验来源、公开性、schema、文件完整性与内容 hash，并在同一个原子采用点切换目录、正文、公开资源和词法搜索投影。动态服务不得读取静态站、博客部署指针、静态 JSON、静态 HTML 或 Release 资产；SSR 必须使用已验证的数据库快照，不得逐页面请求访问 GitHub。相同 commit 与相同内容 hash 无需更新；不同 commit 但内容 hash 相同只更新来源修订，不重建内容或搜索；不同 commit 且内容 hash 不同的候选只有在校验及词法投影准备完成后才可整体采用。语义投影按同一内容快照异步准备，不是内容采用的前置条件；缺失、失败或取消时保留已采用内容并仅向管理员报告语义覆盖不足。并发刷新必须只保留一个任务，目录、详情、资源和词法搜索不得分批生效。Playbook 同步只改变其独立快照与可重建搜索投影，不写入或删除文章/Memo 内容，初始 seed 只有在没有有效数据库快照时才可使用。

### REQ-PBI-009 — 数据库快照回退与首次启动

静态站发布失败时必须继续提供之前成功发布的静态版本。动态服务必须在数据库持久化 current 与 previous 两份完整 Playbook 快照；GitHub 读取失败、候选无效、网络故障、重启或 schema 不兼容时继续使用 current，不自动选择更旧历史。只有在没有有效 current 时才允许使用 seed；没有任何有效快照时，Playbook 必须显示暂不可用，不得以空目录或空搜索结果冒充成功，也不得阻止其他 console 功能启动。静态站版本与动态服务快照可以暂时不同，不能互相覆盖。

### REQ-PBI-010 — 统一搜索与采用快照一致性

统一搜索必须明确区分 Topic、项目实践、Policy Skill、文章和 Memo，并保留剪藏子类型，提供正确的目标 URL 与类型过滤。所有来源由统一服务端契约检索、聚合和综合排序，展示使用单一连续结果列表，不按来源增加分区、标题或独立列表，也不由客户端拼接排名。Playbook 的公开正文与资源必须进入确定性全文检索；现代 RAG 只能判断与当前内容快照一致的 Playbook 候选，资源以不可信证据隔离传入，查询改写仍只作用于博客，向量化不得成为发布或内容采用的前置条件；共同排名不能直接比较独立引擎的原始分数。

静态搜索页使用静态站本批公开数据，console 搜索页和动态公共接口使用数据库 current 快照；二者不得在请求中互相读取或拼接。统一服务在请求开始时绑定当前采用的内容快照身份，旧搜索 URL/API 的版本字段仅兼容接收并忽略，调用者不能选择数据库历史版本。响应可以报告实际采用的来源修订和内容 hash，RAG 只能消费同一内容快照的语义候选。上游路由、section anchor 和公开资源位置必须映射至 Playbook 命名空间，页面 metadata、正文、目标文件和结果不得混用版本。公共 HTTP、现代 tRPC 与 MCP 也必须发现 Playbook；文章/Memo 原有权限与历史接口兼容性继续生效。

内容身份聚合、章节子结果、排序计数与搜索命中高亮分别遵循 `REQ-PBI-012`、`REQ-PBI-013`、`REQ-PBI-014` 和 `REQ-PBI-015`。文章/Memo 的公开搜索 API 必须保留既有 JSON 数组响应及结果字段兼容性；内容聚合不得要求将响应改成 envelope 或暴露内部检索引擎诊断字段。Playbook 的公开来源与内容类型属于结果身份，按统一接口契约提供。

### REQ-PBI-011 — 来源采用可追溯与受控回滚

静态站发布记录继续保存其 Release、包 digest、渲染器 commit 和发布结果；动态同步记录必须保存配置仓库、ref、解析后的来源 commit、内容 hash、检查/采用时间、任务结果及受控失败原因。重试必须可核对到确切输入；普通同步不能执行自动降级或选择旧历史，显式回滚必须通过明确的来源配置或受控运维操作完成。运维能够分别核对静态站发布身份与动态服务 current/previous 快照身份；此能力不依赖访客页面上的版本文案。

### REQ-PBI-012 — 按内容身份聚合

- 同一个搜索内容对象必须只有一个内容搜索结果，归集其整页、章节、命令及公开资源命中；页面级命中不得作为自己的章节子结果。聚合身份由来源、内容类型及规范内容身份共同确定。Playbook使用规范详情路由标识所属对象，规范路由中的章节 fragment 或文件位置不产生新的内容身份；文章/Memo 使用各自类型中的内容身份。
- 搜索文档 ID、标题文字及正文相似程度不得作为跨对象合并依据。同名或同 slug 的不同类型、来源对象必须保持独立；关联的 Topic、项目实践快照和 Policy Skill 各有自己的内容搜索结果，关系链接不构成父子命中。
- 每个主结果必须使用所属内容的权威标题，而不是以某个章节标题替代整篇标题，或通过拆分标题中的分隔符猜测父标题。仅有章节命中、整页未命中时也必须产生所属内容的主结果。无标题 Memo 继续遵循既有标题语义，保留摘要与可访问名称而不补造可见标题。
- 主摘要必须取自该对象的有效匹配片段，保留关键词高亮与上下文。除下述单章节情形外，主入口定位最相关命中的有效章节锚点；最佳命中为整页或没有有效章节锚点时进入规范内容页面。同一对象只有一个可定位章节命中时，主结果直接使用该章节的片段与锚点，不额外显示重复的章节子结果。
- 聚合只能使用搜索页面已绑定的公开内容快照，不得为补齐父标题或章节位置混入另一个 Playbook 内容版本。既有可见性校验与锚点校验必须保留；无法定位的命中不得制造章节链接。

### REQ-PBI-013 — 章节子结果与渐进展开

- 同一内容有至少两个不同的可定位章节命中时，必须在其主结果内部呈现章节子结果。每个子结果显示章节原始标题、该章节的匹配片段及有效跳转入口；主标题只出现一次，不得在子结果中反复拼接整篇标题。
- 子结果必须按规范章节位置去重。同一章节的多个索引文档或重复片段只形成一个子结果，选用其中最相关的命中；不同章节即使标题相同也必须按各自有效锚点保持区分。仅有整页命中或无可定位章节时，只显示主结果。
- 默认必须直接显示最多三个最相关章节，按该内容内的相关性降序排列；相关性相同时按正文顺序稳定排列。超过三个时显示“展开更多匹配（N）”，其中 N 为尚未显示的去重章节数。展开在所属主结果内显示其余章节，支持“收起更多匹配”恢复前三个；至多三个章节时不得出现展开控件。
- 子结果必须采用比主结果弱的层级，通过缩进、文字层级与间距表达所属关系，不得渲染成分散的顶层卡片或重复的卡片套卡片。大屏幕（至少 1024px）采用左侧搜索操作、右侧结果的双栏布局；输入框、分类筛选与建议搜索词集中在左栏，结果使用右栏宽度。较窄屏幕采用上下排列。搜索输入外框与提交按钮的曲率必须协调，按钮上、下、右三侧内缩一致；悬停不移动按钮，加载不改变输入外框高度。章节以两列附属链接展示，移动端为单列。桌面端和移动端采用相同的三个章节阈值，移动端继续使用共享连续阅读承载层与文字边距。
- 主入口、各章节入口和展开控件必须分别可操作，禁止嵌套链接或将整个父卡片链接包住子链接与按钮。键盘可以分别访问可见入口，折叠内容不得进入 Tab 顺序；展开控件必须提供展开状态及受控区域关系，触控目标继承至少 44px 的共享契约。新查询重置展开状态，类型筛选保留当前查询中已有内容的展开状态；收起不改变内容排序、计数或目标 URL。

### REQ-PBI-014 — 内容排序、上限与计数

- 服务端必须按共同相关性规则综合排序所有来源，展示保持该顺序，不按来源分组、拼接或重排。一个内容的章节、命令与资源命中不得累计分数，也不得仅因命中更多提升主结果排名；子结果顺序只在所属内容内计算。同分保持稳定，不能用同步采用时间提高 Playbook 的新鲜度。
- 搜索结果上限必须限制所有来源聚合后的唯一内容数。必须先限定查询范围并完成内容身份聚合，再应用共同排名与一个全局 `topK`；不得为每个来源保留固定名额。禁止先截取固定数量的原始命中再聚合，导致同一篇内容占满候选并丢失其他内容。类型与来源筛选必须检索截断前的合格语料，不能只过滤此前返回的全部前 N 条；关键词命中保全与 AI 剩余容量遵循搜索主题。
- “找到 N 条内容”、全部与类型筛选的数字必须按已返回的唯一内容搜索结果计算，不得把章节子结果或原始命中计入。数字代表返回范围内的内容数，不得冒充全部索引命中的精确总量；展开、收起和同一章节重复命中都不得改变它们。只有一篇内容命中多个章节时，内容数与该类型计数仍为 1。
- 新检索、类型筛选与缓存恢复必须遵循相同的聚合语义，旧的平铺缓存不得重新引入重复结果。聚合适用于正常检索、文章/Memo 语义检索与全文回退的展示结果，不改变各检索路径已有的查询解释与公开权限。

### REQ-PBI-015 — 高亮不改变文字排版

- 所有搜索内容类型的主结果和章节子结果必须遵循相同的搜索命中高亮规则，适用于普通文本与代码片段。高亮只能强调原有匹配文字，不得在文字两侧插入空格、不可见空白或其他占位字符；已有空格、标点、换行及代码缩进必须保持原样，复制所得文本必须与未高亮的同一片段一致。
- 高亮必须保持普通内联文本的排版属性，不得增加 padding、margin、占位边框或改变显示方式。字体、字号、字重、行高、字间距、词间距和断行规则必须继承所在文本上下文；不得通过额外加粗、缩放或不可断行的包装来强调关键词。允许使用文字颜色、背景颜色或不占布局空间的装饰，高亮范围必须贴合匹配文字，不呈现成独立徽章。
- 在字体已加载、容器宽度和内容相同的条件下，高亮前后必须保持每个字符的位置、原有行高、换行位置、总行数及片段容器尺寸一致；高亮不得把相邻文字推开、使整行变高、提前折行或增加横向溢出。明暗主题下高亮保持可辨和可读，状态变化不得引入排版位移。

### REQ-PBI-016 — 访客阅读信息与维护元数据分离

本要求适用于 Playbook 入口、分类索引、Topic、项目实践快照和 Policy Skill 详情中的自动生成信息，以及公开 Markdown 文件的阅读模式。以访客能否理解内容、判断适用性或找到关联实践作为信息保留标准；允许公开的字段并不因此具有展示价值。下表所列维护字段的原始清单必须取消，不以翻译字段名、折叠“更多元数据”或展示格式化 JSON 的方式保留整批维护元数据。

标题、摘要、分类、正文与目录各有自己的语义和位置，不属于原始元数据清单。元信息区不得包含正文段落、章节标题、Markdown 指令或从嵌套配置展平而来的行；上游 `doc_metadata` 即使包含这些内容，也不得直接回显。正文继续由公开 sections 或资源文件中与文件头分离的正文提供，不能因隐藏元数据而丢失正文，也不能把正文搬进 Hero 的元信息区。

| 来源字段或信息 | 访客呈现 |
| --- | --- |
| 内容版本、Release tag、edition digest、源 commit 等发布身份 | 不在访客界面展示，包括 Hero、索引、页脚、提示文字及折叠区域；数据一致性与运维追溯保留完整身份。 |
| `schema_version`、`kind`、`slug` | 不展示；内容类型与标题使用页面已有语义，不重复机器身份。 |
| `routing`、`group`、`match`、`language`、`evidence_policy` 及其子项 | 不展示；它们属于维护或 Agent 路由配置，不形成访客说明。 |
| `confidence`、`last_verified`、`evidence_window` | 默认不展示，不将主观可信度包装成可信声明，也不增加例行维护日期栏。 |
| `status` 表示正常或当前有效 | 不展示常态状态，不增加“当前有效”徽章。 |
| `status` 明确表示过时、废弃或已被替代 | 以“内容已过时”“内容已废弃”或“已有替代内容”等自然中文提示表达实际状态；只有公开数据提供有效替代目标时才显示对应链接。 |
| `primary_projects` | 不作为字段清单展示；复用同一已发布Playbook快照中已有的公开关联项目链接，以项目名称呈现，避免重复列出 slug。 |
| 资源文件自身的 `title` / `name`、`description` | 仅在能帮助识别所选文件且不重复文件已有标题或说明时，作为该文件的名称或简短说明呈现，不渲染为原始键值表。 |
| 未明确约定的字段、空值、重复信息、数组或对象形式的维护配置 | 默认不展示，不把字符串化 JSON、YAML 原文或展平的子键回退为访客内容。 |

可见提示必须基于已知且含义明确的公开数据，不根据核实日期距今多久推断过时，不把未知状态解释为正常、废弃或高可信。没有有用信息时，整个元信息区不生成标题、分隔线、空白占位或展开控件；`status: current` 与其余维护字段不应留下替代信息块。内容版本仅用于已发布Playbook快照的一致性、缓存和发布追溯，不显示“内容版本 v2.4.0”等自动生成的访客文案，也不迁移到页脚、提示框或折叠区域继续展示。标题区域只保留内容类型、标题、简介、分类及确有必要的适用性提示；元信息区不承载摘要或正文。该筛选不删除作者正文、代码示例或资源源码中有实际语义的技术版本。

字段筛选与人类语言呈现必须在静态 HTML 和 console SSR 中生效，禁用 JavaScript 也不得看到原始字段清单；不得通过客户端加载后隐藏、仅用 CSS 遮挡或保持在可访问树中的方式处理。阅读模式不回显解析失败但边界完整的文件头，仍显示其后的正文；源码、下载及同版本公开数据保持完整，展示筛选不能代替已有公开包安全校验。正文中的 YAML 示例与代码块属于阅读内容，不按文件头字段筛除。

### REQ-PBI-017 — 公开内容与附带资源检索完整性

统一搜索必须覆盖已发布公开包中的全部 Topic、项目实践正文、Policy Skill 指令及其附带公开文本文件，包括 references、模板、脚本和配置示例。搜索资料只能来自已经验证的公开 catalog、search payload 与资源文本，不读取工作区、私有源文件或链接所指的其他内容；公开包以外的 Skill 主文档不因名称相同自动纳入。上游缺少资源搜索文档时，消费者必须从同版公开 catalog 的资源文本准备可重建投影，不要求修改原始发布包或访问私有仓库。

资源文件名、有效相对路径和实际正文均可命中；Markdown 按阅读正文及有用名称/简介检索，维护 frontmatter 不成为展示摘要或独立搜索内容。源码与配置示例保留有意义的技术文字，不执行文件或沿链接取内容。指令的正文和 `SKILL.md` 资源副本只形成一个 Policy Skill 结果，安装命令也归入所属对象。

资源命中必须归入所属 Policy Skill，并携带同一快照内有效文件路径、匹配片段及可定位阅读目标；点击应打开并选中实际命中文件，禁用 JavaScript 时仍有可读文件目标。文件位置以规范相对路径标识，不用不稳定的数组序号作跨版本身份。同一文件重复命中只产生一个附属入口，整页、章节和文件共同使用既有默认三个附属入口及展开规则，文件数量不增加内容计数或主结果排名。只有资源命中时，主结果仍显示 Policy Skill 的权威名称并直接定位最佳文件；没有有效文件目标不得伪造链接。

### REQ-PBI-018 — 统一内容同步视图与数量

内容同步管理必须同时列出本地内容来源和独立的 Playbook 来源，所有状态、控制、来源身份、失败详情和历史仅对管理员开放。Playbook 行必须呈现当前内容采用、词法索引条目、语义投影模型与 ready/pending/failed 数量、最近错误、配置仓库/ref、current/previous 快照、来源 commit 和内容 hash。不得把静态站发布身份或 GitHub 当前 ref 的远端状态误称为数据库已经采用。

采用以下可辨认状态：`unconfigured`、`current`、`checking`、`stale`、`failed`、`invalid` 和 `unavailable`。内容可用性、在途任务、来源检查结果、候选状态与 RAG 覆盖是独立事实；未配置、检查中、失败或候选无效时已有 current 仍可读。未观察到来源状态时显示未知，不根据历史数据推断最新或在线。动态服务使用 [GitHub 内容源契约](./contracts/github-source.md) 的实际配置；静态站发布开关不能被误作动态内容源状态。

Playbook 数量按采用快照中可独立阅读的 Topic、项目实践与 Policy Skill 统计。资源文件数和搜索文档数另列，不能混入总内容量；栏目入口、章节、命令及重复文档不计为新内容。总内容量为各来源当前已采用的唯一内容之和，允许本地来源的既有 project 类型独立统计，但不把它与 Playbook 项目实践混同；previous 快照不再次加入总量。来源摘要、逐来源数量和类型统计必须来自同一范围与可核对的内容水位，彼此可加总；已注册源包括实际纳入管理的 Playbook，启用源使用运行时的真实有效配置，不能只统计本地管理器或固定为启用。关闭同步不删除已采用内容，也不把收录总量变为零。

现代 RAG 的管理指标必须同时覆盖博客和 Playbook，并按 [搜索语义覆盖契约](../search-relevance/SPEC.md#req-srel-022--真实-rag-语义索引覆盖) 明确语料范围、内容对象与分块两种单位、总量、已索引、未索引、过时、失败和覆盖率。现有博客向量接口保留兼容边界，其统计不能冒充全部来源的现代 RAG 覆盖；本地 project 等已收录但不参加对应 RAG 范围的对象不得混入 RAG 分母。页面区分内容采用、词法可查询、语义覆盖、任务进度与模型策略可用性；Playbook 缺少向量不表示内容同步失败，idle 只表示当前没有任务。读取中、未知、接口失败和真实零值必须可辨认。

### REQ-PBI-019 — 动态检查触发与来源隔离

动态 Playbook 检查必须在服务启动时执行，并按可配置间隔后台检查，默认间隔为五分钟；管理员可以手动触发异步检查。普通请求不得触发或等待 GitHub 读取；读取状态本身只读，不触发新同步。本地内容同步与 Playbook 检查保持独立，手动与自动 Playbook 检查共用同一调度和采用边界，同一来源最多一项在途任务，重复请求复用已有任务。

现代 RAG 必须提供管理员可明确选择博客、Playbook 或全部来源的补建与重建操作；全部范围不得静默只处理 post/memo。任务范围、当前模型、Playbook 完整采用快照、内容与分块进度和失败原因均可查看，取消指向对应任务。语义补建可作用于未变化的已采用版本，不要求再次采用新内容或改变采用时间；内容检查与语义重建保持独立，读取状态和普通搜索不得隐式启动模型任务。既有博客专属操作继续明确标注其范围。

各来源独立完成并报告结果；一个来源失败不能回滚另一个来源已经成功完成的合法操作。全量本地同步、取消、向量化和数据重置不能清空 Playbook；Playbook 检查不能修改文章/Memo。取消必须指向明确任务并在原子采用前生效，采用已完成时返回已完成，不能以取消隐式恢复旧版本。停用自动同步不删除当前快照，实际网络禁用配置不得被手动按钮绕过。

动态后台不得选择任意 Release、读取静态站指针、触发应用发布、修改静态发布开关或执行自动回滚。自动与手动检查只访问配置 GitHub ref 的固定公开导出，不新增浏览器凭据；显式来源回滚必须通过受控配置或运维操作完成，普通同步本身不获得降级权限。

### REQ-PBI-020 — 同步记录、恢复与查询就绪

Playbook 的自动与手动尝试必须进入同一可持久读取的来源历史与日志，区分成功采用、无需更新、失败、取消，记录任务来源、开始/结束、阶段、目标/采用身份、数量变化与受控错误。未改变版本的成功检查不得重置内容采用时间。重启后仍能查询最后结果，不能仅依靠进程内计数或控制台输出解释失败；日志不得包含凭据或无关正文。

本地与 Playbook 的同步摘要、最近结果和任务历史必须持久可读。“累计同步”须明确计数单位为已结束的来源任务；一次全部来源请求可关联多个来源任务，重复请求复用同一任务时不得重复累计。成功、无需更新、失败、取消分别可查，注册日志、单文件处理日志和向量分块日志不能当作同步任务累计。最近检查、最近成功同步与最近内容采用分别记录，包生成时间不冒充检查或采用时间。分页、展示条数和日志保留不改变持久累计数。旧数据无法可靠还原的累计或采用时间显示未知或明确记录起始范围，不从普通日志行数、文件数或重启时间伪造历史。

候选校验、目录/正文/资源读取和词法搜索投影准备成功后，在一个原子点切换当前采用版本；语义投影随后按同一内容快照异步准备，不阻塞合法内容采用。语义准备过程中崩溃、持久提交失败、部分失败或取消时保留已采用且可查询的内容，标记 pending/failed 并仅向管理员报告 RAG 覆盖不足；GitHub 读取、候选校验、词法投影或采用前操作失败时保留 current，没有旧版时报告不可用，不以空目录或空搜索列表冒充成功。新的目录、正文、资源与词法搜索整体可见，previous 只用于受控恢复，不由普通请求自动选择；语义向量不得跨内容快照或模型借用。相同 commit 与内容 hash 重复检查无需更新；不同 commit 同 hash 只更新来源修订；在途旧任务不能覆盖更晚采用结果。所有读取、索引准备和操作都有明确预算，不在请求路径执行全量准备。

首次采用、镜像 seed 恢复、自动轮询采用、手动采用及有效 embedding 配置改变必须共用可恢复的语义准备边界。启动先恢复 current/previous 的采用身份、语义覆盖和未完成任务，再进行有界后台补建与轮询；未遍历分块也必须可计入未索引总量，不能依赖逐块插入 pending 后才知道还有多少工作。部分失败、中断和取消不把未处理部分报告为零或已完成；旧版投影单独保留与核对，不能凑进当前版覆盖。自动和手动重复请求、进程恢复与迟到任务均不得重复创建相同目标的在途任务或覆盖更晚目标。

### REQ-PBI-021 — 项目技术栈可读展示

项目实践页 MUST 递归解析结构化或字符串化 JSON 技术栈，隐藏空值与维护身份字段，按“运行与交付、依赖与工具、配置与质量、其他信息”提供紧凑标签页，已知字段使用中文标题，未知键保留可读标题，技术值不翻译。分组不得形成分栏或嵌套卡片；标签页支持方向键、Home、End 和可见焦点。

标量数组 MUST 使用水平 chip，折叠时按实际可用宽度显示完整的一行，在最后一个可见项之后紧接 `+N` chip；只有放不下的项目被折叠，不按固定数量隐藏可容纳内容。展开后可换行显示全部项目，收起恢复单行；极长首项允许省略但保留完整值提示。嵌套对象数组使用紧凑列表，超过八项时先显示前四项并可展开剩余内容。字段标签使用同一对齐列。

“查看原始数据” MUST 是低强调的次级入口，折叠时为平面工具栏，展开时允许显示完整 JSON 面板。两种状态保持相同工具栏高度、左右 12px 内边距和按钮坐标，分隔线及描边不影响布局。原始 JSON 提供主题高亮、图标复制和真正铺满视口的全屏阅读，图标通过 tooltip 与可访问名称说明用途；全屏支持 Escape、焦点与滚动位置恢复。复制失败时清理临时节点、提供可访问反馈并展开原始内容供手动选择；无 JavaScript 时通过原生折叠入口阅读完整筛选数据。筛选不改变上游公开数据合同。

### VER-PBI-019 — 手动、自动与多来源任务

- Method: 分别触发本地同步、启动检查、默认轮询和管理员 Playbook 检查，叠加重复手动请求，注入缺少 token、某一来源失败、取消前/后原子采用、网络禁用及本地全量同步；分别补建和重建博客、Playbook 与全部语义投影，包括 commit 不变但向量缺失的情况，检查权限、来源数据和任务结果。
- covers: `REQ-PBI-008`, `REQ-PBI-019`
- Pass condition: 单来源操作不扩大范围，同一目标的重复请求只执行一次；普通请求不触发 GitHub；未变化内容仍可补建语义投影且不改变内容采用时间。独立成功保留，取消有明确任务与阶段。既有 Playbook 不被本地操作删除，手动检查不绕过配置，不访问静态站或私有源文件，不执行发布/自动回滚。

### VER-PBI-020 — 采用、持久记录与崩溃恢复

- Method: 检查 commit/hash 不变、新 commit 同 hash、新 commit 新 hash、首次 seed、自动采用、管理员采用、部分语义准备与恢复；注入 GitHub 读取、公开边界、digest/schema、搜索投影准备与持久提交失败；在准备和采用边界退出并重启，提交迟到任务和失效租约，检查 current/previous 读取、持久任务计数、分页与有限历史的兼容范围。
- covers: `REQ-PBI-007`, `REQ-PBI-008`, `REQ-PBI-009`, `REQ-PBI-011`, `REQ-PBI-020`
- Pass condition: 经过校验的目录、正文、资源和词法搜索在同一采用点可查询；相同内容只更新必要来源元数据，新内容整体采用；语义投影失败或取消不撤销已采用内容，而 GitHub/词法/采用前失败保留 current，无快照明确不可用。所有采用路径异步准备同版投影，重启保留状态、待补量与任务结果；摘要累计不归零、不随分页减少、不按日志行数膨胀，未知旧历史范围明确。无需更新不改变采用时间，旧任务不覆盖新结果，日志能核对目标/采用身份且不含凭据或无关正文。

### VER-PBI-021

- Method: 使用现实项目 Web Demo 的正式路径，检查递归 JSON、空值和维护字段过滤、四类分组、未知键、重复 chip、长值及不同宽度；检查标签键盘操作、chip 开合、原始面板工具栏坐标、高亮、复制成功与失败、全屏及退出，以及无 JavaScript 原生展开。
- covers: `REQ-PBI-021`
- Pass condition: 1280、393、320px 无页面横向溢出，折叠 chip 始终单行且 `+N` 紧邻可见项目，展开不丢值；工具栏开合各控件坐标不变且与代码区同为左右 12px 内缩；原始数据折叠无卡片边框，全屏占满视口，关闭后焦点和滚动恢复，明暗主题沿用共享 Nature 样式。
