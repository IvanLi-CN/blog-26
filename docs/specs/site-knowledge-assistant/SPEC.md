# 站内知识助手与 AI 用量

本文定义静态公开站与动态前台共用的站内知识助手、私人对话、前台身份、个人配额和后台 AI 用量统计。实现覆盖见 [IMPLEMENTATION.md](./IMPLEMENTATION.md)，兼容背景见 [HISTORY.md](./HISTORY.md)。

## Context and Scope

- Context: 登录用户需要在阅读站内内容时持续问答，并可在浮动面板与完整界面之间继续同一条对话。既有剪藏讨论属于这套对话能力；普通用户临时使用，管理员持续使用，后台需要区分个人额度与全站 AI 消耗。
- In scope: 站内知识问答与来源引用；静态站及动态前台的统一入口、对话面板、完整界面与对话切换；前台身份；剪藏对话归并与旧记录归属；对话保留；Token 与问答次数配额、单用户恢复；后台用户列表、仪表盘和运营用量模块。
- Out of scope: 通用角色系统、游客问答、单用户定制配额、管理员浏览他人私人对话、按价格折算账单、外部递归研究、任意工具执行和自动内容发布。剪藏抓取、摘要与翻译继续由剪藏主题定义；公开评论的审核、删除与布局继续由评论主题定义。

## Terms and Interfaces

- 领域术语以 [GLOSSARY.md](../../../GLOSSARY.md#站内知识助手) 为准，包括前台用户、站内知识助手、助手对话、临时助手对话、个人助手用量、问答次数、配额恢复和全站 AI 用量。
- 前台用户可来自可信管理员账号或 GitHub 读者登录；管理员无需绑定 GitHub。后台管理认证与前台身份分别授权。
- 助手对话属于一个前台用户，可以携带剪藏阅读上下文；公开评论与私人助手对话不共享正文或可见性。
- Interface: 公开站和动态前台的共享阅读外壳、登录状态接口、私人对话及生成接口、完整对话路由、管理员用户列表、仪表盘、运营 AI 用量模块和全局配额配置。静态构建只携带界面与公开内容，私人状态从受信任运行时读取。

## Requirements

### REQ-SKA-001 — 站内知识问答

- 助手 MUST 支持多轮问答，按需检索调用者获准访问的站内内容，并在使用站内资料回答时提供可定位的来源引用。
- 回答 MUST 区分来源内容与推断；没有取得材料、检索失败或证据不足时必须如实说明，不得虚构已阅读的内容或来源。
- 助手 MUST 沿用站点配置的 LLM 能力与凭据解析边界，不向浏览器暴露模型密钥，不因本功能增加任意 shell、凭据或内容发布权限。

### REQ-SKA-002 — 统一前台用户

- 前台身份 MUST 同时支持可信管理员账号与 GitHub 读者登录。管理员自动拥有前台用户身份，不以绑定 GitHub 为前提，头像使用站点页脚的站长头像。
- 已绑定的 GitHub 身份 MUST 仍可识别其管理员资格；同一管理员通过这些已确认的身份入口访问时必须归属于同一个前台用户，不能形成重复的本人对话列表或用量归属。
- 服务端 MUST NOT 按未经认证的邮箱、昵称或可变 GitHub login 猜测管理员资格。显式绑定与历史评论归属保护继续有效。
- 前台身份 MUST 同样供公开评论与回复使用；服务端确认的管理员新评论直接通过审核、保存管理员作者属性并使用站长头像，不要求 GitHub 绑定。
- 前台助手 MUST 依据自己的有效登录身份授权，后台登录过期不能直接锁定前台对话；后台操作仍必须通过独立管理员认证。

### REQ-SKA-003 — 使用与隐私权限

- 问答、私人历史、对话列表及生成状态 MUST 仅向有效登录的对话所有者提供。普通用户只能检索公开可读的站内内容；管理员前台用户可检索非公开站内内容。
- 管理员待遇 MUST NOT 自动授予读取其他用户私人对话的能力。列表、消息、流事件、续传与所有写入口必须执行相同归属检查。
- 检索及材料读取 MUST 由服务端校验当前访问资格，不能依赖前端隐藏入口。静态产物、发布快照、公共缓存和访客响应不得包含私人消息、私人生成状态或非公开检索材料。

### REQ-SKA-004 — 浮动入口与面板

- 静态站与动态前台 MUST 提供右下角浮动对话入口。桌面打开悬浮面板，小屏打开自底部向上滑出的抽屉。
- 面板 MUST 能读取消息、发送消息、停止生成，并提供切换或新增对话入口；切换列表在面板内操作，不要求先离开当前阅读页。
- 面板 MUST 提供放大入口，导航到完整对话界面并继续当前对话、草稿和生成状态。
- 未登录者 MUST 得到明确登录入口与不可直接使用的说明；登录回跳保留原阅读位置与未提交文字，不能自动代用户发送消息。

### REQ-SKA-005 — 完整界面与共享状态

- 完整对话界面 MUST 在桌面左侧展示本人对话列表，右侧展示当前记录及消息输入区域；小屏必须仍能切换、新增和继续对话。
- 完整界面与浮动面板 MUST 共用当前对话、消息、未提交文字和生成状态。放大、缩回面板或切换呈现方式不得复制会话、重复提交消息或重启生成。
- 本人一般对话与剪藏关联对话 MUST 出现在同一个列表中；列表只能返回本人的记录。

### REQ-SKA-006 — 草稿与剪藏入口选择

- 新建动作 MUST 先展示空草稿，首次发送用户消息才创建持久对话并占用名额；单纯打开面板或新建界面不占用名额。
- 在剪藏详情首次打开入口时，MUST 优先继续当前用户与该剪藏已有的对话；尚无对应记录则展示带剪藏上下文的草稿。
- 面板已经打开时，页面导航 MUST NOT 自动替换当前对话。名额已满时必须说明原因，并让用户选择已有对话或删除后新建，不能静默删除旧记录。

### REQ-SKA-007 — 剪藏属于统一对话

- 剪藏讨论 MUST 使用统一身份、对话模型、列表、入口和界面，不能保留互相隔离的另一套私人对话功能。
- 同一份剪藏下不同用户的对话 MUST 分别归属本人、互不可见。原文、可用译文、摘要与备注作为获准的阅读上下文；无原文时不得声称已阅读文章。
- 同一目标重处理 MUST 保留已有对话连续性；更换剪藏目标必须区分新旧阅读上下文，不能把旧消息静默归到另一篇文章。对话列表保留本人仍在保留期内的旧对话，不因此增加处理版本历史或手工恢复界面。
- Memo 公开 MUST NOT 公开其私人对话，普通用户的剪藏对话与一般对话共用相同名额、保留期及配额。

### REQ-SKA-008 — 临时保留与管理员待遇

- 普通用户 MUST 最多同时保留三个对话。每条对话在最后一条用户消息之后七天到期，新的用户消息刷新到期时间；助手输出、打开或浏览对话不能刷新期限。
- 前台 MUST 明确提示临时使用、到期时间与当前名额，支持用户删除本人对话。到期或删除必须清理消息内容、释放名额；实际用量不能退回或删除。
- 管理员 MUST 不受对话数量、自动过期、个人 Token 或问答次数配额限制，实际 AI 消耗仍需统计。

### REQ-SKA-009 — 生成独立于视图生命周期

- 关闭面板、导航、切换对话或放大界面时，生成 MUST 继续，并保存进度和结果。刷新或短暂断线后必须能恢复查看，不能自动重复发送用户消息。
- 用户 MUST 能明确停止生成；连接断开或界面卸载不得被当作主动停止。同一次提交的传输重试和恢复不能生成重复用户消息。

### REQ-SKA-010 — Token 配额窗口

- 普通用户个人助手用量 MUST 受滚动最近一小时和最近七天两档配额限制，默认分别为 10,000,000 与 100,000,000 Token，任一档不足均限制继续问答。
- 这两档上限 MUST 可由后台全局统一配置，不支持单用户自定义上限。旧消耗移出窗口后额度逐步恢复。
- 前台 MUST 展示两档剩余额度及下次恢复时间，额度不足时保留草稿并提供明确反馈；服务端必须校验额度，不能仅限制前端按钮。

### REQ-SKA-011 — 用户维度计量

- 个人助手用量 MUST 仅计入本人助手问答及该轮检索实际触发的 AI 调用，以实际输入加输出核算。输入包括系统提示、历史、检索材料与缓存命中输入；输出包括回答与思考消耗，按提供方字段包含关系去重，不能重复累计。
- 已取消、失败及重试实际产生的消耗 MUST 计入。用户维度必须展示输入、输出和总量，该加总规则不能被当作全站运营指标的统一口径。
- 问答内部的多步模型调用 MUST 归属发起用户及对应功能；公开搜索等其他独立功能的消耗不扣个人助手配额。

### REQ-SKA-012 — 问答次数限制

- 普通用户 MUST 另受滚动最近一小时六十次、最近七天三百次的默认问答次数限制，两档上限可由后台全局配置。
- 每条用户消息开始处理后 MUST 计一次；用户主动重试另计一次。内部检索、多步调用、自动重试或同一提交的传输恢复不能额外扣问答次数。
- 前台 MUST 展示剩余次数及恢复信息；任一 Token 或次数窗口不足均限制新问答，管理员不受这两类上限约束。

### REQ-SKA-013 — 单用户配额恢复

- 后台 MUST 允许管理员对一个用户执行配额恢复，同时恢复小时与七天窗口的 Token 和问答次数可用额度至全额。
- 恢复 MUST 只改变后续可用配额，不能清零用户列表、真实用量历史或运营统计，也不能改变全局上限或建立个人专属上限。

### REQ-SKA-014 — 缺失用量

- 调用失败、中止或缺少完整提供方 usage 时，个人配额 MUST 允许保守估算占用并标明估算，后续取得实际用量时校正，不能重复扣除。
- 全站原始记录 MUST 保留缺失或不完整状态，估算值单独记录；缺失不能冒充零消耗或精确实际值。

### REQ-SKA-015 — 全站计量范围

- 后台 AI 用量 MUST 统计全站实际 AI 调用，包括助手、检索、搜索、剪藏、标签整理等功能和管理员使用产生的消耗。
- 每次实际模型调用 MUST 单独计入运营调用次数，包括内部调用与自动重试；可确认的用户、功能、模型和执行结果必须可追溯。无法确认用户时应明确未归属，不能猜测用户身份。
- 引入计量前缺乏可信 usage 的历史调用 MUST NOT 被伪造成有精确 Token 的记录。

### REQ-SKA-016 — 提供方原始口径

- 运营记录 MUST 保留提供方原始输入、缓存命中、输出、思考等分项及其包含关系，并区分成功、失败、中止、缺失及不完整用量。
- 聚合与图表 MUST 避免重复累计包含字段；估算与实际数据分别标识。模型或提供方不具备某分项时不得编造。
- 运营 MUST 能按时间、功能、模型和用户分析调用及分项用量，不把用户额度合计口径强加给原始运营指标。

### REQ-SKA-017 — 后台用户列表

- 后台 MUST 提供覆盖前台用户的用户列表，显示可识别身份、管理员资格与归属于该用户的全站 AI 输入、输出、总 Token 消耗，支持查看最近小时、最近七天及累计消耗。实际消耗与只覆盖助手的个人配额必须明确区分。
- 用户列表 MUST 展示真实用量与估算标识，不能把恢复后的配额余额误标为已消耗量。已确认属于同一管理员的身份不得重复计入两个人。
- 单用户配额恢复 MUST 可从对应用户操作，并清楚说明真实历史不清零。

### REQ-SKA-018 — 仪表盘最近一周

- 后台仪表盘 MUST 增加最近七个自然日且包含今天的 AI 消耗统计卡与每日堆叠图，使用清楚标明的一致统计时区。
- 统计卡 MUST 展示输入、缓存命中、输出和调用次数，并能辨认执行结果及缺失用量；不能以缺失为零掩盖统计不完整。
- 每日堆叠图 MUST 分为未缓存输入、缓存命中输入、输出，按提供方包含关系处理思考等子项，不重复堆叠。功能、模型等更细分析由运营模块提供。

### REQ-SKA-019 — 运营用量模块

- 后台运营区域 MUST 增加 AI 用量模块，提供比仪表盘更详细的时间范围选择、跨范围趋势、按用户/功能/模型分组及调用明细。
- 模块 MUST 支持预设与自定义时间范围，展示调用次数、成功/失败/中止、原始 Token 分项、缺失与估算情况，并区分明细保留期内与仅有每日汇总的范围。
- 全局配额配置与用量管理 MUST 由后台管理员认证授权，不能因前台管理员待遇或 GitHub 身份绑定而开放后台接口。

### REQ-SKA-020 — 用量保留

- 调用明细 MUST 保留九十天，按用户、功能、模型形成的每日汇总长期保留，支持累计消耗及长期趋势。
- 汇总 MUST 保留必要分项、调用结果及缺失/估算含义，明细清理不能再次增加或减少已汇总用量。
- 用量记录 MUST NOT 额外复制提示词或回答正文；对话删除、过期及配额恢复均不能清除真实用量统计。

### REQ-SKA-021 — 旧剪藏讨论迁移

- 具有可信剪藏创建者的旧讨论 MUST 整体迁移至该创建者的统一对话列表，保全既有消息和阅读上下文。
- 旧讨论未记录逐条发言者时 MUST NOT 猜测逐条作者。无法确认归属的记录必须原样隔离保留，等待人工确认，不能自动分配给另一个前台用户或直接删除。
- 旧共用讨论模型 MUST NOT 延续为管理员可自动读取其他用户新私人对话的权限。

### REQ-SKA-022 — 响应式与可控验收

- 公开界面 MUST 遵循 Nature 响应式、主题、对比度和控件尺寸契约；抽屉必须处理焦点进入与返回、背景滚动、安全区、软键盘、未提交草稿及阅读位置，减少动态设置下仍可操作。
- 后台基础交互 MUST 使用本地 UI primitives。页面级证据必须来自正式路由的独立构建 Web Demo，共享 Inspector 覆盖访客、普通用户、管理员、配额耗尽、临时对话到期、缺失用量、生成中、失败和重连等场景。
- Web Demo MUST 使用隔离 fixture 和模拟操作，live 产物不能通过浏览器开关变成 Demo；模拟验收不能向真实模型发出调用或访问真实私人数据。

## Verification

### VER-SKA-001 — 身份与权限

- Method: 静态站与动态前台组合验证访客、普通 GitHub 读者、未绑定管理员、已绑定管理员、他人会话、后台登录过期、伪造身份和共享缓存。
- covers: `REQ-SKA-002`, `REQ-SKA-003`, `REQ-SKA-017`, `REQ-SKA-019`
- Pass condition: 管理员无需 GitHub 即拥有一致的前台身份、站长头像与本人列表；后台过期不直接锁定仍有效的前台身份，前台资格不替代后台认证；普通用户检索公开内容，管理员可检索非公开内容，所有身份都不能越权读取他人私人对话。

### VER-SKA-002 — 知识与剪藏上下文

- Method: 使用可控检索材料和模型双桩，覆盖有来源、无证据、资料不可用、剪藏无原文、译文后完成、同目标重处理及目标更换。
- covers: `REQ-SKA-001`, `REQ-SKA-007`
- Pass condition: 回答引用实际获准材料且不虚构读取；剪藏使用统一私人对话，材料更新与目标更换不混淆历史，也不提供任意工具或发布权限。

### VER-SKA-003 — 对话入口与响应式

- Method: 正式路由 Web Demo 覆盖静态与动态入口、桌面/小屏、浮动面板/完整界面、切换/新增、剪藏入口、登录回跳、软键盘、主题、焦点、减少动态及配额场景。
- covers: `REQ-SKA-004`, `REQ-SKA-005`, `REQ-SKA-006`, `REQ-SKA-022`
- Pass condition: 面板内可切换和发送，放大继续同一对话；首次发送前不占名额，剪藏优先续聊，页面导航不替换已打开对话；无横向溢出、重复挂载或重复发送，草稿、阅读位置与可访问操作保全，live 与 Demo 隔离。

### VER-SKA-004 — 保留与生成生命周期

- Method: 可控时钟、删除与到期清理、并发新建、生成中导航/关闭/切换/刷新/断线、重复请求与主动停止。
- covers: `REQ-SKA-008`, `REQ-SKA-009`
- Pass condition: 普通用户最多保留三个对话，仅用户消息刷新七天期限，删除和到期释放名额但不退用量；管理员不自动过期；生成持续并可恢复，同次提交不重复，主动停止可辨认。

### VER-SKA-005 — 个人配额

- Method: 可控时钟与提供方分项 fixture 覆盖滚动窗口边界、全局配置、缓存/思考包含关系、内部调用、人工/自动重试、失败/中止、估算校正、并发提交及单用户恢复。
- covers: `REQ-SKA-010`, `REQ-SKA-011`, `REQ-SKA-012`, `REQ-SKA-013`, `REQ-SKA-014`
- Pass condition: 默认 Token 与次数上限正确，任一窗口不足阻止新问答；个人仅核算助手及其检索，内部分步不多扣问答次数；估算明确且不重复校正；恢复同时补满四档可用额度，真实历史与全局配置保持正确，管理员不限额。

### VER-SKA-006 — 全站运营计量

- Method: 可控 AI 调用 fixture 覆盖各功能、管理员、未归属调用、内部调用、自动重试、提供方分项差异、成功/失败/中止、缺失及不完整 usage，检查用户列表、统计卡、堆叠图与运营筛选。
- covers: `REQ-SKA-015`, `REQ-SKA-016`, `REQ-SKA-017`, `REQ-SKA-018`, `REQ-SKA-019`
- Pass condition: 所有实际调用进入运营统计且不冒充个人助手用量；原始分项可追溯，七个自然日含今天，堆叠不重复计算缓存/思考；筛选、累计、明细和汇总保持一致，未知量不显示成精确零值。

### VER-SKA-007 — 用量保留与清理

- Method: 可控时钟验证九十天边界、重复汇总、明细清理、长期按日查询、对话删除/过期与单用户配额恢复，并检查用量字段不携带正文。
- covers: `REQ-SKA-020`
- Pass condition: 明细按期清理，每日汇总及累计消耗长期可查，清理和恢复不改变真实用量，统计记录不另存提示词或回答。

### VER-SKA-008 — 历史迁移

- Method: 使用可信创建者、缺失/不可信归属、当前及旧目标讨论、无逐条作者、重复迁移和管理员未绑定 GitHub 的隔离 fixture。
- covers: `REQ-SKA-021`
- Pass condition: 可归属记录完整且幂等地进入创建者列表，无归属记录原样隔离，没有作者猜测、丢失消息或对其他用户开放的旁路。
