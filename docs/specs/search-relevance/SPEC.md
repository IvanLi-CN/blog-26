# 三种搜索模式与可靠关键词回退

> 本文件定义长期搜索契约；实现方案与覆盖状态记录在 `IMPLEMENTATION.md`，兼容关系记录在 `HISTORY.md`。

## Context and Scope

站内搜索提供一个“智能搜索”三选一控件：关闭、LLM + RAG、LLM 查询改写。未指定时默认关闭智能搜索，由关键词全文检索快速返回基础结果；选择任一 AI 模式时，AI 补充与基础结果统一参与相关性排序，同时保护合法关键词命中不被删除。两种 AI 模式独立执行，不互相串联或接管故障；任一不可用时，以用户原始查询直接回退到关键词搜索。三者都返回实际站内内容列表，不生成问答。原始关键词命中不能被模型删除，结果数量不要求填满，内部排名值不作为可信百分比。三种模式共用内嵌 Tantivy 全文检索。

- In scope: 公共搜索页面、公共 HTTP、tRPC 与 MCP 中的模式选择，文章、Memo、剪藏及已发布 Playbook 的确定性检索，跨来源排序、范围筛选与截断，回退和搜索元信息。
- Out of scope: 生成式问答、内容发布权限的改变、文章与 Memo 列表的既有排序、私有 Playbook 内容、legacy semantic 的 Playbook 扩展，以及 Playbook 上游发布流程的改变。

## Terms and Interfaces

- 领域术语使用 [GLOSSARY.md](../../../GLOSSARY.md) 中的 RAG 搜索、查询改写搜索、关键词搜索、搜索回退和关键词命中保全。
- 模式标识为 `rag`、`rewrite`、`keyword`；搜索模式与查询语法分类是两个独立维度。
- 关键词命中是符合受控查询含义的内容；不把查询词自动改成内容类型筛选条件。
- RAG 的语义补充是没有进入原始关键词集合、但通过有效上下文判断的内容；改写补充只满足受控改写查询，不声称经过内容语义判断。
- 返回上限限制唯一内容搜索结果的数量，不表示索引命中总量，也不要求填满。
- `/api/public/search` 的数组响应及公开权限继承 [搜索语法与全文回退契约](../search-full-text-fallback/SPEC.md)。
- 各入口共用三种模式，已有 enhanced 兼容入口路由到 RAG；独立 semantic 仍表示显式底层语义检索，不是页面中的第四种模式。
- 现代统一入口为 `/api/public/search`、tRPC `search.content` 和 MCP `search_content`；跨来源输入、结果与版本元信息见 [统一搜索接口契约](./contracts/unified-search.md)。来源、类型、查询模式是三个独立维度。

| --- | --- | --- | --- | --- |
| RAG | `rag` | 查询与已检索、已授权的有界候选上下文 | 关键词命中保全，与 LLM 判断后的补充统一按相关性排序 | 原始查询的关键词搜索 |

## Requirements

### REQ-SREL-001 — 关键词命中保全与统一排序

两种 AI 模式必须独立取得用户原始查询的合法关键词集合，再与有效补充统一排序。当关键词命中不超过返回上限时，所有合法命中必须进入结果，不得因为模型改写、不在向量候选中、缺少向量、重排低分或推测语境不同而遗漏。命中超过上限时，先按关键词相关性与稳定同分顺序确定返回范围；模型可以在候选集合内改变排序，但不能换入范围外内容或删除合法关键词命中，补充不得挤掉受保护的关键词容量。不能通过对混合结果直接截取前 N 条实现保全。

单独搜索 `Node` 时，包含 `Node.js` 的内容属于实际文字命中，不得因其 JavaScript 运行时含义而被排除；上下文判断可以影响排序，不能取消命中。只在参考链接中提到 SQLite 的内容必须保留，但真正介绍 SQLite3 的可信语义内容可以排在它前面。

### REQ-SREL-002 — 有效补充与数量上限

RAG 补充必须通过有效上下文判断，不得把向量前 N 名、本批最高分或每批归一化分数视为相关性证明；未判断候选不返回。改写补充必须实际满足有效受控改写查询，不能由 LLM 编造文档、链接或排名。两者按内容身份去重后应用上限；实际有效内容只有少量时只返回这些内容，完全无关输入允许无结果。

### REQ-SREL-003 — 明确查询含义

普通空白分隔多词采用 AND；支持引号短语、`slug:`/`title:`/`excerpt:`/`body:`/`tags:` 字段、AND/OR/二元 NOT、括号及词或短语末尾的显式 `*`。NOT/AND 优先于 OR，括号改变优先级，引号中的操作词仍是文字。引号、字段、布尔条件、括号、前缀与非法高级语法的文字重试直接执行关键词搜索，不进行模型改写、名称扩展或语义补充。空白查询返回空列表且不调用 AI；`文章` 是检索文字，不能被模型解释为内容类型筛选。

新 Tantivy 引擎不编译 `NEAR(...)`。新搜索入口识别该位置语法后交由既有 SQLite FTS5 查询执行器处理，保留 NEAR 的顺序、距离和错误语义，不静默改成普通文字。普通文字 `NEAR` 与引号内的 `"NEAR(alpha beta, 3)"` 可以按文字检索。其他非法高级语法继续按文字项 AND 重试；预算超限直接拒绝，不进入文字重试。独立 semantic 与内容列表保留旧查询行为。

### REQ-SREL-004 — 真实结果元信息

公开搜索结果不得展示“相关度 XX%”或把内部排序值表达为可信概率。内容类型、摘要与原文命中高亮保留；语义和改写补充不得假造原始查询命中。可以高亮原文实际存在的有效别名或改写词，但不能伪装成原始拼写；可访问元信息同样准确。高亮不改变原文、空白、代码缩进或布局。关键词、回退、明确语法及受控错误的空态推荐词只能走确定性来源，不自动发起旁路 AI 请求或恢复旧 AI 推荐缓存。

### REQ-SREL-005 — 内容与接口边界

公开权限、私有与草稿排除、剪藏可见性、无标题 Memo 展示和规范 URL 必须生效。检索及模型上下文只能包含当前调用者可访问内容，返回前再次校验身份与可见性。跨类型同 slug 不合并。公开 HTTP 兼容 JSON 数组，模式状态通过独立响应元信息提供，不要求修改已有结果对象；提供方错误及密钥不对读者公开。

### REQ-SREL-006 — Playbook 来源边界

Playbook 必须在关键词、RAG 和 AI 回退时参与原始查询的确定性检索，并与文章/Memo 在同一返回范围内综合排序；查询改写只为文章/Memo 补充查询，不读取或改写 Playbook。不得按来源固定拼接、独立分配显示名额或通过前端补取形成不同入口的搜索语义。目录、指令、章节和公开资源命中属于页面绑定的已发布 edition，并按规范内容身份聚合。

RAG 的模型上下文、向量候选和相关性判断可以包含同一已采用公开 edition 的 Playbook 标题、正文、章节和资源，但必须把资源正文作为不可信证据隔离传入，不能执行其中指令；查询改写仍只作用于文章/Memo，不能读取或改写 Playbook。仅搜索 Playbook 时可以执行 RAG 候选判断，但没有语义投影时应以同版词法候选继续并报告覆盖不足。向量化、LLM 配置与质量验证都不得成为 Playbook 发布或内容采用的前置条件。

### REQ-SREL-007 — AI 不可用时直接关键词回退

所选 AI 模式关闭、未配置、依赖不可用、超时、输出无效、预算不足或质量策略未通过验证时，直接以用户原始查询执行关键词搜索。不转入另一 AI 模式，不使用失败前的改写查询回退，也不放行未经判断的向量结果。正常无结果不是不可用，不触发换模式；关键词引擎故障为受控错误，不伪装为成功空结果。

### REQ-SREL-008 — 模式入口一致

公共 HTTP、tRPC 与 MCP 共用三种模式、命中保全、质量与回退规则，新调用者可明确指定模式；未指定模式统一默认 `keyword`。已有 enhanced 入口保留数组响应和历史参数语义：`rerank=false` 关闭重排但继续语义检索，`rerankerModel` 仍覆盖旧重排模型；旧嵌入模型参数仍只表示 embedding。新策略配置独立于旧 reranker 参数。

各入口尊重其已有返回上限；新模式不借兼容入口扩大扫描或权限。公共 HTTP 保留数组响应，模式元信息包含所选模式、实际模式和受控执行原因；新模式 API 明确返回同等元信息，旧 enhanced 保持数组结构。独立 semantic 保留显式底层语义检索及既有权限、类型、预算和嵌入故障回退，不作为页面的第四个选项；MCP 非公开访问继续要求管理员授权。

### REQ-SREL-009 — 技术名称与文字片段的匹配准确性

三种模式共用的普通名称匹配必须避免错误子串命中：`Arch` 命中 `Arch Linux`、`Arch-Linux` 与 `中文Arch中文`，不得因包含相同字符而把 `archive`、`search`、`aarch64`、`ArchLinux` 或 `arch_linux` 算作关键词命中。中文支持连续文字片段，如 `文章` 可以命中 `这篇文章`，不得命中 `文隔开章`、`文。章`、`文 章` 或 `文-章`。英文技术名称匹配忽略 ASCII 大小写；名称边缘的 ASCII 字母、数字、下划线、加号和井号属于延续，点号、连字符、斜杠及中英交界可以构成边界。`Node` 可以命中 `Node.js`，`ESP32` 可以命中 `ESP32-C3`；`SQLite` 不字面命中 `SQLite3`，`C++` 不字面命中 `C++17`。版本扩展可使用显式前缀、有效受控改写或 RAG 补充，不能冒充原始文字命中。

技术名称中的标点必须按输入保留：`C`、`C++`、`C#` 不得混同，`Node js` 不得作为 `Node.js` 的实际文字命中。匹配、查询正规化与高亮不得改变已显示的原文；中文片段不附加英文名称的外侧限制，中英混排按输入边缘分别判断。查询端继续使用既有 NFKC 正规化；本主题不新增文档端全角、重音或其他 Unicode 拼写等价规则。

需要英文词首匹配时使用显式前缀语法，如 `arch*` 可以命中 `architecture`，但不得命中 `search` 或 `aarch64` 中间的文字；`sqlite*`、`C++*` 可用于版本名称。匹配规则必须用实际内容验证，不能以“英文完整词”这一名称替代技术符号、中英混排、分隔符和原文位置的明确处理；采用某个 tokenizer 或新增索引本身不构成准确性证明。字段作用域、布尔组合与非法语法文字重试按受控解释执行；NEAR 位置语法由 SQLite FTS5 保持旧行为。原始子串候选必须在应用结果上限之前完成有效命中校验，不得先取前 N 条再过滤而遗漏有效命中。

### REQ-SREL-010 — 两种 AI 各自的质量依据

RAG 的内容判断与查询改写分别使用与有效模型、提示词、输入及输出策略匹配的验证依据，不互相借用结果。RAG 覆盖同义概念、正文相关性及无关候选；改写覆盖有效转换、无关输入、过度放宽和名称混淆。模型自报置信度、每批分数拉伸和 mock 测试不能替代实际模型验证；没有匹配依据时回退关键词。模型或策略变化后重新验证，不能用全部拒绝来声称正例通过。

### REQ-SREL-011 — 新策略与缓存隔离

新策略隔离旧服务端 AI 缓存及旧浏览器结果缓存。AI 缓存区分模式、查询含义、权限、模型、提示词、质量策略与输入身份；每次执行取得当前原始关键词集合，返回前校验权限，不能通过最终结果缓存绕过这些步骤。失败与关键词结果不进入 AI 结果缓存；浏览器恢复结果不能让另一模式或较旧请求覆盖当前选择。Playbook edition 缓存保留。

### REQ-SREL-012 — 有界处理与稳定排序

查询解析、候选检索、正文上下文、模型请求和结果数量都有明确预算，不全量载入正文交给模型，不以静默截断冒充完整执行。解析保留最多 2,048 个 Unicode 码点、128 个词法 token、32 层 AST 的既有硬界限，新的引擎编译成本另有硬上限；旧 SQLite 的 256 SQL 参数预算不能被误称为 Tantivy 查询预算。RAG 整体输入不足以可靠判断时回退关键词，个别未判断候选不返回；查询改写只生成有限受控查询，不执行任意 SQL、引擎 DSL、工具循环或扩大权限范围。名称校验先于排序和显示截断，同分采用稳定的时间与内容身份顺序。

### REQ-SREL-013 — 名称别名与多义简称

普通查询必须支持已确认的名称别名组，`NodeJS`、`Node.js` 与表示 JavaScript 运行时的 `Node` 可以互查。确定别名 `NodeJS` 与 `Node.js` 双向形成关键词命中，语义能力不可用时仍有效；搜索 `Node` 时，`Node.js` 通过实际文字命中、`NodeJS` 通过确定目标名称的别名命中进入关键词集合。

搜索 `NodeJS` 或 `Node.js` 扩展到只有 `Node` 拼写的内容，需要 RAG 确认其 JavaScript 运行时上下文；不要求正文另含完整名称，也不放行只有图或集群节点含义的内容。关键词和查询改写模式不无条件扩展到多义简称，模型改写不能通过生成 `Node` 绕过该边界。判断不可用时跳过补充；这个限制不反向取消原始查询成立的文字命中。

别名必须来自明确核对的映射，不得通过删除标点、截取英文前缀或猜测技术词自动产生。别名扩展保持普通多词 AND 的条件结构；引号、字段、布尔表达式、显式前缀及非法高级语法的文字重试不自动扩展名称别名。展示只高亮内容中实际存在并成立的拼写，不能将别名伪装成原文已有的查询拼写。

### REQ-SREL-014 — 三种独立执行链

`rag` 先检索可访问候选，再让 LLM 阅读上下文、判断相关性并排序；`rewrite` 只让 LLM 理解或改写查询，之后由全文引擎执行与排序，LLM 不接收站内目录、候选摘要、正文或检索反馈；`keyword` 直接执行原始查询的确定性全文搜索。三种模式均返回真实内容列表，不生成问答。

两种 AI 模式可以共享全文引擎、权限及底层模型提供方，但各自拥有策略、缓存、预算和可用性判断。RAG 不调用改写模式，改写不依赖向量、嵌入、RAG 索引或内容重排；一条链的故障不能错误标记另一条链不可用。

### REQ-SREL-015 — 手动选择与实际模式

页面提供“智能搜索”三选一控件：关闭、RAG、AI 改写，并说明两种 AI 补充方式的差别。未指定时默认关闭智能搜索（`keyword`），URL 中的显式有效模式始终优先，非法模式值返回受控输入错误。切换后以同一原始查询重新执行；查询、所选模式及已有筛选可以通过 URL 表达，刷新、分享与前进后退保留选择，旧请求及缓存不能覆盖新选择。

回退时明确说明当前结果使用关键词搜索，保留用户选择，下次请求仍可尝试该模式；不永久改选或自动轮询。高级语法直接关键词执行时，同样如实表示实际模式。加载、无结果、筛选后为空、AI 回退和全文引擎故障是可区分状态，不将错误显示为空结果。控件、键盘操作、触控目标、明暗主题、移动结果流及首屏信息密度遵循共享公开 UI 契约。

### REQ-SREL-016 — 内嵌成熟全文引擎

三种模式及 enhanced 入口的文章与 Memo 全文检索采用内嵌 Tantivy 磁盘索引，由 Bun 的受控原生接入层调用，不要求部署独立搜索服务。引擎负责倒排索引、查询执行及全文相关性排名；项目仅负责规则配置、受控查询编译、权限、同步与编排，不自写通用分词器或全文评分引擎，也不以全量正文后过滤弥补名称错误。

支持的发布平台必须有可加载的原生发行物，实际发布镜像必须通过加载与异步查询验证；原生调用不能阻塞 Bun 的服务事件循环。锁定依赖、构建、收集原生文件及开发平台的接入方式属于可复现项目资产，不能依赖机器上临时编译的产物。独立 semantic、列表的 SQLite 索引及 Playbook 引擎保留各自职责。

### REQ-SREL-017 — 可重建索引与当前内容一致性

Tantivy 索引是可重建投影，不替代现有文件内容与 SQLite 的存储责任。路径必须隔离开发、测试及生产，索引 schema、分析器及别名策略的版本可辨认；writer 的所属进程明确，同一索引不能被多个 writer 并发写入。新增、修改、删除、改名、类型、标签及可见性变化覆盖所有内容写入入口，数据库事务回滚不发布索引变更，重放幂等，崩溃后可以恢复。

请求以开始时的内容版本为一致性基线，全文快照达到对应变更水位后才可返回成功；等待有硬预算，未准备就绪、提交失败、坏索引或版本不兼容为受控不可用状态，不能用旧结果或空列表冒充当前关键词命中。候选进入 LLM 和最终返回前仍校验当前权限与版本，撤回公开内容不得泄漏；不向模型发送已过时正文。索引检查、显式重建及版本更换的安全切换可执行且可验证，不在每次请求中触发无界重建。

### REQ-SREL-018 — 独立配置与有效可用性

两种 AI 模式分别拥有启用状态、模型配置引用、提示词与输出策略、时间与 token 预算、质量依据及缓存身份；允许引用同一现有 chat 提供方，不要求额外购买或配置不同模型。RAG 另外依赖 embedding 和向量状态，但缺失时仍可用同版词法候选进入模型判断并报告覆盖不足；改写及关键词不依赖 Playbook 向量，既有 rerank 提供方不能自动当作候选内容判断用的 chat 模型。未验证的配置不能静默启用 AI 补充。

模型、有效端点、凭据、提示词、名称策略或质量依据变化使受影响模式的旧可用性结论与缓存失效；一条链的失效不污染另一条链。调用者只收到受控状态，运维可定位实际模式、回退原因和各阶段成本，日志不包含密钥或未经授权的内容。

### REQ-SREL-019 — 跨来源相关性与统一容量

选择全部时，所有来源的合格内容必须通过共同、确定性的相关性规则综合排序。不得固定文章优先、Playbook 优先、按来源分段或轮流交错；Tantivy、MiniSearch 等独立引擎的原始分数和各批次归一化分数不能直接比较。共同排名必须能区分标题或主题中的直接命中与仅在参考链接中的弱命中，且同等匹配证据不因来源改变而受到优先或降权。沿用成熟全文引擎的检索职责，不以新增自制通用评分引擎替代现有职责边界。

先校验查询与权限、限定来源和类型、完成内容身份聚合，再按共同排名选择最多 `topK` 个唯一内容；上限为整个结果集的上限，不是每个来源各自的上限。章节和文件的重复命中不得累计提高所属内容的排名。同分先沿用原有内容时间语义，再按来源、类型及规范内容身份形成稳定顺序；不存在作者内容时间的 Playbook 不以下载或采用时间冒充新内容。同一输入身份下结果必须可复现。

原始查询在当前范围内的全局前 `topK` 个合法关键词内容构成受保护集合，其中包含 Playbook。AI 补充可以参加综合排序，但不能挤掉该集合；当关键词不足上限时才使用剩余容量。AI 不可用时重新按原始查询的确定性共同排名返回，不要求填满。

### REQ-SREL-020 — 全入口与截断前筛选

网页、console、HTTP、现代 tRPC 与 MCP 必须使用同一个服务端结果契约，覆盖文章、Memo、剪藏、Topic、项目实践和 Policy Skill。网页不得继续独立拼接 Playbook 排名。来源筛选与内容类型筛选必须作用于合格语料，发生在排名与容量选择之前；仅过滤已返回的全部前 N 条不满足筛选要求。保留 `all`、`post`、`memo` 的输入兼容；剪藏仍是 Memo 的显示子类型。互不匹配的来源和类型返回空集合，不扩大范围。

HTTP 保持 JSON 数组；现代 tRPC/MCP 保持结果与所选/实际模式的 envelope。文章/Memo 既有字段和规范路由继续有效，Playbook 增加明确类型、来源、目标 URL 及可用的章节或资源位置；内部版本与不完整范围状态通过独立元信息传递，不显示成访客版本文案或概率。各入口保留默认值与最大 `topK`，相同查询、模式、范围、可用版本和上限下的内容身份及顺序必须一致。旧 enhanced 的数组、模型覆盖与 `rerank=false` 语义继续兼容；独立 semantic 不自动变为统一全文检索。

### REQ-SREL-021 — 搜索版本与范围可用性

网页和所有现代搜索入口在请求开始时固定当前采用的 Playbook 快照。旧链接或调用者携带的 `edition`、`sourceReleaseId`、`sourceTag` 仅为兼容接收并完全忽略，不能选择版本、改变缓存身份、触发冲突或进入 RAG 候选；新搜索 URL 不写入这些字段。除这三个遗留字段外，未知搜索输入仍由各入口拒绝；SSE 对受控搜索错误保留与 JSON 等价的 code/message。请求期间只能使用开始时快照的标题、正文、资源、索引和锚点；响应仍可报告实际使用的完整 provenance，供诊断和同版向量隔离。服务端只能使用已验证且已采用的本地内容与同版词法投影；语义投影缺失时可以继续使用同版词法候选并报告覆盖不足，不在页面或搜索请求中下载上游或进行全量重建。

当前快照不存在时，仅 Playbook 范围为受控不可用；全部范围可保留文章/Memo 结果，但必须报告 Playbook 范围不完整，不能以空结果冒充已完成检索。有效旧快照仍可查询时，同步失败本身不使搜索失败。Playbook 故障不得改变文章/Memo 的权限检查和原始内容水位要求。版本化阅读页、章节 anchor、资源下载和内部语义投影继续使用完整 edition 身份；非搜索 API 的版本校验不变。

### REQ-SREL-022 — 真实 RAG 语义索引覆盖

管理员必须能够查询现代 RAG 的全部、博客与 Playbook 范围，明确区分当前 RAG 语料中的唯一内容对象和预期语义分块。管理统计默认反映公开检索的实际准入规则；已授权的非公开范围若提供统计，必须显式标注且单独计算，不能混入公开覆盖。总量从当前合格语料与有效分块规则得到，不从已有向量记录反推；没有任何 embedding 行的合格内容仍计入总量与未索引。博客使用当前内容身份和水位，Playbook 绑定完整 edition/Release ID/tag；current 与 previous 分开，过期版本、无当前父内容的历史记录和不准入类型不增加当前总量。收录总量与 RAG 总量不得互相冒充。

两种单位均须报告总量、已索引、未索引、过时、失败及覆盖率，并标明来源、访问范围、有效 embedding 配置与统计身份。分块仅在属于当前预期集合、输入摘要与有效模型/配置匹配、向量存在且维度与数值有效时计为已索引；存在旧索引但不符合当前要求计为过时，从未建立有效索引的预期分块计为未索引，当前目标的最新准备失败单列失败。失败优先于过时，过时优先于未索引，每个分块只进入一个当前状态。排队与运行属于任务进度，不替代索引状态，pending 行不能证明整个未处理集合已经被列出。

RAG 主卡以唯一内容对象为展示单位，直接呈现总量、已索引、未索引、过时、失败及内容覆盖率；分块总量、分块状态和分块覆盖率放入详情并明确标注单位。同一文章、Memo、Topic、项目实践或 Policy Skill 的多个分块不能放大主卡计数，所属资源也不独立计为内容。来源切换时主卡和详情使用同一范围与版本，详情可解释部分覆盖及其失败或过时分块；不以历史向量记录数替代主卡内容数。

内容对象只有全部预期分块均为已索引时才计为已索引；部分覆盖须可辨认且不能计为完整。未完整覆盖的对象按失败、过时、未索引的顺序归入一个摘要状态，并在详情保留各分块事实。内容状态和分块状态分别满足“总量 = 已索引 + 未索引 + 过时 + 失败”；覆盖率分别为已索引除以同单位总量，空语料显示不适用而非未经验证的 100%。模型未配置、内容或统计不可用与真实零值区分，孤立或已撤权记录只可作为管理员诊断信息，不成为有效覆盖。

RAG 语义覆盖、后台任务 idle/running、RAG 策略启用和模型质量验证是独立状态。搜索运行时的模型、Base URL 和 API Key 必须来自既有 `llm_settings`；`search_settings` 只保存模式开关、预算和可选模型覆盖，不保存或替代提供方配置。管理员状态中的 `available` 只表示模式启用且提供方配置完整，`qualityStatus` 单独表示 `not-run`、`passed`、`failed` 或 `stale`；质量状态缺失、失败或过期不阻止已配置模式执行，真实提供方故障仍按现有规则回退关键词。管理页须显示按来源的内容与分块指标、最近索引时间、任务进度及受控错误；接口、页面与搜索元信息必须使用相同的目标身份和新鲜度判定。`ragIncompleteSources` 依据当前请求所选范围的实际语义覆盖是否完整，不能依据本次是否有向量候选、命中多少结果或关键词是否已满 topK 推断完整；部分未索引、失败或过时须报告对应来源。覆盖不足时继续保留同版词法候选与现有模型失败回退，不改变实际模式兼容或触发查询内补建。

### REQ-SREL-023 — 语义准备与现有索引兼容

博客与 Playbook 的语义补建必须按照统计所用的目标集合、摘要与配置生成索引，确保任务完成后相同目标能够被判为有效覆盖；源文件摘要、embedding 输入摘要和分块摘要不能混用。目标变化使旧任务结果对当前覆盖失效，重试失败或缺失目标不能重复放大数量。语义分块规则改变或内容缩短后的多余旧分块不计入当前覆盖，切换分块/整篇模式的旧记录不冒充当前预期集合。

现代 RAG 继续兼容既有博客 post_embeddings，legacy semantic 和 enhanced 的既有参数、数组/envelope、访问范围及权限边界保持有效。旧记录只在身份、输入和配置均与当前目标匹配时计入有效覆盖；不能仅因无错误信息或有非空向量而认定完成。不以统计修复为由自动清空历史索引、扫描私有来源、改动上游发布流程或变更 RAG 排名规则。

### REQ-SREL-024 — AI 搜索的流式等待与兼容入口

公共 JSON 搜索入口必须继续保持数组响应、响应头元信息和既有 10 秒策略预算，供兼容调用者使用。RAG 与查询改写的正式页面请求可以使用 `/api/public/search/stream`，服务端必须先发送 `started` 事件，再发送阶段进度或不超过 2 秒的 SSE 注释心跳，最终发送完整 envelope 的 `result` 或受控 `error` 事件。流式执行的 embedding 和模型判断单次等待上限不得超过 30 秒，必须把客户端取消传入 provider 请求；断开连接后不得发送迟到结果或继续无界执行。SSE 不改变候选、权限、版本、排序、关键词命中保全或模型失败回退，tRPC、MCP、legacy semantic/enhanced 保持原响应形状。

- covers: `REQ-SREL-001`, `REQ-SREL-003`, `REQ-SREL-004`, `REQ-SREL-007`, `REQ-SREL-009`, `REQ-SREL-013`
- Pass condition: 搜索 Node 时 Node.js 和 NodeJS 不因推测语境或低模型判断被删除；确定别名在关键词及回退时互查成立。搜索 NodeJS/Node.js 时，只有 Node 的运行时内容可由 RAG 判断后补充，其他节点被拒绝；关键词和改写不无条件扩展 Node。明确语法不扩展别名，高亮保留实际拼写。

### VER-SREL-012 — 执行链独立

- Method: 记录各模式依赖调用；使 RAG 向量或判断失效后验证改写，使改写策略失效后验证 RAG。
- covers: `REQ-SREL-007`, `REQ-SREL-014`
- Pass condition: 两者不调用对方，故障独立；改写模型只接收查询和静态策略，没有内容目录或检索反馈；三者只返回内容列表。

### VER-SREL-013 — 选择与回退状态

- Method: 切换、刷新和分享模式 URL，在旧请求延迟时再次切换；检查回退及高级语法后的下一次普通查询，在桌面和共享契约要求的移动宽度检查控件。
- covers: `REQ-SREL-008`, `REQ-SREL-011`, `REQ-SREL-015`
- Pass condition: 默认关闭智能搜索（关键词全文检索），有效 URL 选择优先，非法模式受控提示；原始查询按选择重搜，关键词命中被保全并与 AI 补充统一排序，旧结果不覆盖新选择。刷新、分享与历史导航可还原状态，实际模式准确，回退不永久改选，触控及键盘操作成立，空结果和错误可区分。

### VER-SREL-014 — 原生发行物与引擎职责

- Method: 在实际发布镜像及受支持开发平台加载打包产物，执行磁盘检索、异步并发与定时器探针；检查分析器配置、受控 AST 编译和全文调用边界，记录完整代表性内容集的索引大小、内存和阶段延迟。
- covers: `REQ-SREL-009`, `REQ-SREL-012`, `REQ-SREL-016`
- Pass condition: 无额外搜索服务即可运行，原生文件随发行物分发且可复现；支持的查询规则由引擎在截断前执行，事件循环可推进，没有自写倒排索引、全文评分或全量正文后过滤，代表性成本有实测依据。

### VER-SREL-015 — 索引变更、恢复与可见性

- Method: 从文件同步、路由、MCP 和批量恢复分别变更内容，覆盖新增、编辑、删除、改名、类型、标签、发布和撤回；注入事务回滚、writer 冲突、提交失败、提交前及 checkpoint 前退出、索引滞后、版本不符和重建切换。检查请求水位及候选判断前和返回前的当前权限。
- covers: `REQ-SREL-001`, `REQ-SREL-005`, `REQ-SREL-007`, `REQ-SREL-017`
- Pass condition: 重放与重建得到相同当前可访问集合，无重复、丢失或撤回内容泄漏；不可用状态明确报错而非返回旧快照或空列表，等待有界，开发、测试及生产索引互不污染。

### VER-SREL-016 — 配置与可用性隔离

- Method: 共用及分别配置 chat 提供方，切换各模式启用、模型、端点、凭据、提示词、预算与质量策略；撤销 RAG 的 embedding 配置，检查改写和关键词仍可执行，检查缓存与运维状态。
- covers: `REQ-SREL-007`, `REQ-SREL-010`, `REQ-SREL-011`, `REQ-SREL-014`, `REQ-SREL-018`
- Pass condition: 每条 AI 链依据自己的有效配置决定可用性并直接回退关键词；chat 与 rerank 角色不混淆，共用提供方不造成链间调用，过期配置依据及缓存失效，读者和日志不暴露密钥或越权内容。

### VER-SREL-017 — 综合排名与全局容量

- Method: 对每种来源构造标题直接命中、正文专题命中与仅参考链接命中的受控相关性对照；互换来源但保留匹配证据，重复同一章节与文件，覆盖 `topK=1/2/20`、缺少内容时间、关键词满额/未满额及 AI 补充。
- covers: `REQ-SREL-001`, `REQ-SREL-006`, `REQ-SREL-019`
- Pass condition: 直接专题命中排在弱参考命中前，非同分结果不因互换来源改变相对次序，全部返回数不超过一个全局上限；同分按稳定规则处理、重复命中不涨分，合法关键词受保护，RAG 只读取同版公开 Playbook 候选并隔离资源证据，rewrite 不读取 Playbook。

### VER-SREL-018 — 入口、范围与筛选

- Method: 用相同输入比较网页、console、HTTP、tRPC 和 MCP；令全部前 20 条均为文章，同时保留 21 位之后的 Policy 命中，再单独筛选 Policy 与 Playbook。覆盖来源/类型交叉、剪藏、旧字段与旧 enhanced/semantic 参数。
- covers: `REQ-SREL-005`, `REQ-SREL-008`, `REQ-SREL-020`
- Pass condition: 同版本同上限结果身份和顺序一致；单独筛选能发现全部截断范围之外的合法内容；数组/envelope、旧参数与权限保持兼容，计数只计算返回的唯一内容，客户端不另行拼接排名。

### VER-SREL-019 — 当前快照与局部故障

- Method: 搜索过程中采用新快照，分别使用无版本参数、当前/上一版/畸形遗留版本字段及相同 digest 不同 Release 的旧链接；注入无快照、索引未准备、同步失败和断网，检查缓存、资源目标及元信息。
- covers: `REQ-SREL-011`, `REQ-SREL-017`, `REQ-SREL-021`
- Pass condition: 每次成功检索只使用请求开始时的 current 快照并报告实际身份，遗留版本字段不产生冲突或改变结果；全部范围的局部不可用可辨认，仅 Playbook 范围不返回成功空列表；版本化阅读/资源路由仍保持原有校验，请求不访问源仓库或进行全量构建。

### VER-SREL-020 — 两种单位与真实覆盖

- Method: 构造多个内容及重复章节、资源和不同分块数，覆盖完全无记录、部分完成、内容/模型/配置变化、空向量、错误维度、非有限数、失败、孤立记录、草稿/私有/剪藏权限与 current/previous；比较管理接口、页面、全来源和单来源指标，并注入接口读取失败。
- covers: `REQ-SREL-022`, `REQ-SREL-023`
- Pass condition: 两种单位的总量均来自合格目标集合，各状态互斥且可加总；主卡按唯一内容对象显示六项指标，分块数量和覆盖率只在标明单位的详情中展示。一个 Policy Skill 的 50 个分块及附带文件仍只计一个内容对象，部分缺失时主卡不能计为已索引；切换来源后主卡和详情的范围、版本一致。全无记录仍显示正的总量及未索引数，旧记录、无父内容、权限不符及旧版不算已索引，部分准备、失败与过时不冒充完整，读取失败不伪装为零；模型配置或空语料的不可用/不适用状态明确。

### VER-SREL-021 — 补建、兼容与覆盖元信息

- Method: 按当前输入摘要准备博客和同版 Playbook，覆盖增量跳过、失败重试、内容缩短、分块规则与整篇模式切换、重启、模型切换和迟到任务；分别在零/一个/多个语义候选与关键词满 topK 时执行现代 RAG，比较管理覆盖和响应元信息，并回归 legacy semantic/enhanced。
- covers: `REQ-SREL-006`, `REQ-SREL-007`, `REQ-SREL-008`, `REQ-SREL-021`, `REQ-SREL-022`, `REQ-SREL-023`
- Pass condition: 准备与统计使用同一目标/摘要/有效配置，完成后对应目标判为已索引；重复补建不增量膨胀、旧或多余记录不冒充完整。任何所选来源覆盖不全均报告 ragIncompleteSources，包括仍有语义候选或关键词满额的情况；词法集合保全、模型失败回退和同版绑定继续成立，旧接口与授权边界兼容，统计与查询不隐式启动生成。

### VER-SREL-022 — AI 搜索流式传输

- Method: 使用确定性 Mock provider 延迟 embedding 和模型判断，比较 JSON 与 `/api/public/search/stream`，读取首个事件、心跳、最终 envelope，并在结果前取消请求；覆盖 RAG、改写、provider 超时、Web Demo fixture、URL 切换和旧 JSON 调用。
- covers: `REQ-SREL-007`, `REQ-SREL-008`, `REQ-SREL-012`, `REQ-SREL-024`
- Pass condition: 流式入口在模型完成前发送 `started`/进度或心跳，30 秒内的慢 provider 返回实际 AI envelope，取消后没有迟到写入；超过上限或实际 provider 故障仍受控回退关键词。旧 JSON、tRPC、MCP 和 legacy 入口的数组/envelope 与执行语义不变。
