# 项目运行数据 Tooltip 设计

本文记录 `/projects` 开发工具分组中 Codex Vibe Monitor、Tavily Hikari、OctoRill 三个项目运行数据面板的逐格读取需求与推荐设计。匿名数据边界、按住巡视与松手关闭、滚动和巡视的优先关系已经确认；具体参数与兼容性通过实现验证收敛。

长期交互契约以 [Nature UI Spec](./specs/nature-front-ui/SPEC.md#project-runtime-cell-tooltips) 为准，当前实现覆盖与待完成部分见 [IMPLEMENTATION.md](./specs/nature-front-ui/IMPLEMENTATION.md#runtime-cell-tooltip-and-touch-inspection)。本文保留参数建议与技术取舍，不另建主题 Spec；相关领域术语见 [GLOSSARY.md](../GLOSSARY.md)。

## 已确认的需求与数据边界

- 鼠标悬浮在三类方块上时，使用组件库 Tooltip 展示该方块的数据。
- 触屏在图表区域长按时，抑制原生上下文菜单并展示 Tooltip；手指保持接触并移动时，读取接触位置对应的方块。
- Tooltip 必须避开手指的遮挡区域。
- OctoRill 只展示匿名刷新新鲜度状态，不增加仓库名称或精确刷新时间，不扩充公共接口。
- 触摸采用按住巡视、松手立即关闭的生命周期，不在松手后固定 Tooltip。
- 滑动先于长按识别时，保留页面纵向滚动与卡片轨道横向浏览，并取消该次长按候选；长按识别成功后，持续接触的移动仅用于巡视方块，直到松手或取消。

本需求的交互变更集中在逐格 Tooltip 与长按巡视。CVM 与 Hikari 的活动图方块保持信息展示面语义，普通点按不新增行为；移动端短触不打开 Tooltip，只有识别成功的长按进入巡视，也不从方块新增详情导航。OctoRill 的有效新鲜度方块继续保留独立详情链接，标题、摘要和外部快捷入口沿用现有导航。

| 图表 | 方块含义 | 推荐 Tooltip 内容 |
| --- | --- | --- |
| Codex Vibe Monitor | 一个日期的 Token 消耗量 | 日期；`Token 消耗量：2.121B Token`，按 `K/M/B/T` 自动升级量级，避免出现多个千分位分隔符。 |
| Tavily Hikari | 一个日期的请求次数 | 日期；`请求次数：34.182K 次`，按 `K/M/B/T` 自动升级量级，避免出现多个千分位分隔符。 |
| OctoRill | 一个匿名仓库的刷新新鲜度状态 | `最近成功刷新：4 小时内`、`4–12 小时前`、`12–24 小时前`、`超过 24 小时`或`从未成功刷新`，按接口状态表达。 |

数字为文案示例，不是实时数据。日期使用接口给出的日历日期，不转换成设备时区，也不另行聚合。零活动量必须展示为 `0`；缺少数据不得转换成零。日历边界补位不代表活动数据，不产生 Tooltip。

## 仓库现状

`site/components/projects/RuntimeCellGrid.tsx` 现在由 CVM、Hikari 和 OctoRill 共享，保留原始日历日期、原始数值和匿名新鲜度状态；活动图 Tooltip 在展示层按 `K/M/B/T` 自动升级量级，避免出现多个千分位分隔符。`RuntimeActivityChart.astro` 与 `ProjectRuntimeDataPanel.astro` 只负责 Astro 布局和数据注入。格子通过公共 Nature Tooltip 提供 hover、键盘和受控触摸巡视，空槽与未占用区域不产生虚构数据。

公共 `src/components/ui/tooltip.tsx` 以 Radix Tooltip 为基础并使用 Portal、碰撞边距和 Nature tokens；后台 `apps/admin` 仍拥有独立的 Soft UI 包装。两者共享交互基础但不共用主题样式。

`site/lib/project-runtime-live.ts` 通过 `project-runtime-channel.ts` 发布可重放的最新模型，避免响应早于岛屿 hydration 时丢失；触摸巡视期间只保留最新待应用响应，失败回退、Astro 页面切换和隐藏页面都会清理浮层与监听器。项目视觉已拆成独立的 poster/detail 链接与 runtime 图表层，使焦点和导航拥有合法的 HTML 目标。

## 推荐交互模型

桌面 hover 首次显示使用组件库的短延迟，建议 `150ms`；同一图表内移动到另一格时直接更新内容，不重复等待。Tooltip 锚定当前格，进入 Tooltip 本身时保持显示，移出方块与 Tooltip 后关闭；`Escape` 可关闭，键盘焦点保持在图表中。触摸事件不经过桌面 hover 路径，避免手指刚落下就提前出现提示。

触摸采用等待长按、巡视、结束三个阶段。建议长按阈值为 `500ms`，识别前允许 `8 CSS px` 的抖动；识别前明显移动时，取消本次长按候选，保留页面纵向滚动与卡片轨道横向浏览。已经开始滚动的手势不再升级为巡视。识别成功后高亮当前格，持续按住移动按坐标重新命中方块，此时移动不滚动页面或卡片轨道，并消费该次成功长按产生的后续点击，避免跳转详情或再次打开 Tooltip。松手立即关闭长按 Tooltip 并清除巡视高亮，取消触摸、第二根手指、失焦、页面隐藏或切换也结束巡视。活动图普通点按保持无操作；移动端未识别为长按的短触不打开 Tooltip，OctoRill 有效新鲜度链接的普通点击继续导航。

图表整体是触摸巡视区域，方块保持现有数据密度。命中使用接触中心，不偏移到手指上方；只移动 Tooltip 的显示位置。格子间隙可在相邻有效格之间按中线分配，以避免滑动时闪烁；日历边界补位、没有数据的不可见位置、OctoRill 未占用的空间不吸附到远处方块。移出当前图表隐藏提示，仍保持接触回到同一图表可继续巡视；本次手势不跨卡片自动激活另一张图表。

触摸 Tooltip 优先放在当前图表上方的稳定位置，切格时主要更新内容，避免小格移动造成浮层抖动。定位在视口内维护手指避让区域，建议以触点周围至少 `48 CSS px` 的区域为初始值并根据接触尺寸增大；上方空间不足时选择有足够空间且不与避让区域相交的侧向或下方位置。没有合适的邻近位置时使用视口上方的安全位置，仍为同一个 Tooltip；不得通过普通 collision flip 把提示放回指腹下。最终距离与文字尺寸需要移动设备验证。

键盘建议每张图表只有一个 Tab 停靠点，进入后用方向键逐格移动，`Home`/`End` 到首末有效格，焦点或当前格变化展示相同数据，`Escape` 关闭、Tab 离开。通过恰当的图表/网格语义和当前格描述暴露数据，避免把 90 个乃至数千个方块全部加入顺序 Tab 导航。Tooltip 为纯信息浮层，不接受焦点，不包含可点击操作。

## 组件与更新边界

在公共组件库中提供基于现有 Radix 依赖的 Tooltip 包装，继承统一的浮层语义、Portal 和视口避让，使用 Nature tokens。三张卡片的图表共用受控显示与手势控制层；日活动格提供日期与原始数值，仓库新鲜度格提供状态文案，页面不自行拼出另一种 Tooltip 外观。

桌面定位依赖当前格，触摸定位依赖图表与触点避让区域；二者应由公共 Tooltip 的锚定能力表达。原始数值必须从首次渲染与实时更新两条路径保留，不得从已经缩写为 `M`/`B`/`K` 的字符串反推精确值。Radix 的默认触发处理不提供长按巡视，受控层需要防止默认 pointerdown/click 关闭行为与巡视冲突。

建议持续按住巡视时保留图表数据快照，接收的新数据暂缓应用到该图表，结束后应用最近一次有效响应。这样连续滑动不会因刷新重排而把当前方块偷换成别的数据。失败回退立即结束交互。OctoRill 只有匿名状态顺序，不把数组序号宣称为跨刷新稳定的仓库身份。

详情导航与图表焦点必须在 HTML 上分开，不能把新的交互网格或 Tooltip Trigger 嵌入整幅视觉的链接中。调整 DOM 与焦点结构时，活动图方块保持信息展示面，普通点按不打开 Tooltip；移动端只有识别成功的长按进入巡视。OctoRill 有效新鲜度链接保留详情目标，标题与摘要继续链接到详情，外部快捷入口继续链接到其原有目标。成功长按产生的后续点击由巡视控制器消费，独立活动图点击不得新增详情导航。

## 长按与滚动的技术取舍

浏览器在触摸起始时确定 `touch-action` 允许的原生操作，中途改变该属性无法保证接管同一触摸；浏览器开始平移后可取消 Pointer Events 流，pointer capture 也不能阻止原生平移。不能把“长按后修改 touch-action 并捕获 pointer”作为保留原生滚动且保证连续巡视的实现承诺。[Pointer Events 的直接操作规则](https://www.w3.org/TR/pointerevents3/#determining-supported-direct-manipulation-behavior)

推荐评估局部 Touch Events 仲裁：非被动 move listener 在手势开始前就存在，识别等待期只取消抖动范围内的可取消 move；一旦超过阈值，放行原生滚动并永久取消本次候选；识别成功则取消后续可取消 move，进入坐标巡视。规范允许先取消小幅 move 再放行滚动，但一旦放行了 move，后续阻止滚动的行为依浏览器实现而定。因此已经开始滚动的手势不能再升级成巡视，且该方案必须以真实浏览器验证为准。[Touch Events 的取消与移动规则](https://w3c.github.io/touch-events/#the-touchmove-event)

局部 `contextmenu` 处理、`user-select: none` 与 Safari 的 `-webkit-touch-callout: none` 覆盖图表热区，成功长按后的合成 click 单独抑制。菜单抑制不扩大到整张卡片、页面文本或外部链接。已确认优先保留长按识别前的原生双向滚动，接受抖动范围内的小幅初始仲裁，并以目标浏览器验证为兼容性门槛。图表不从触摸起点无条件采用 `touch-action: none`；如果目标浏览器无法满足先滚动与先长按的区分，回到需求决策，不能自行改成禁用图表滚动。

## 验收建议

- 三种图表的 hover、键盘与长按显示同一格的数据，活动图数值按 `K/M/B/T` 自动升级量级且不出现多个千分位分隔符，OctoRill 五类状态全部可解释；零、缺失和边界补位被明确区分。
- 长按前上下滚动和横向换卡仍可用；长按成功后任意方向巡视不产生页面或卡片滚动，不出现上下文菜单、文本选择或详情跳转。
- 活动图普通点按保持无操作；移动端未识别为长按的短触不打开 Tooltip；OctoRill 有效新鲜度链接、标题与摘要导航及外部快捷入口保持现有行为；长按后的点击抑制不误伤下一次独立链接点击。
- 按住跨多格、穿过间隙、移出后返回、松手、取消、多指、页面切换、数据刷新及失败回退均无残留提示或错误高亮。
- Tooltip 不与触点避让区域相交、不越出视口、不被卡片或轨道裁切；文字完整可读且不通过省略号隐藏数据。
- 保持现有 4:5 项目视觉槽位与全部数据格，打开、更新、关闭 Tooltip 对槽位及卡片文案位置的影响不超过 `1 CSS px`。
- 在桌面与窄屏、light/dark/system、文本放大、reduced motion 下验证；重点覆盖 iOS Safari、Android Chrome 及触屏桌面设备。合成事件可验证状态机，不能单独证明原生滚动仲裁与菜单抑制。
- 组件级覆盖放在复用 Tooltip/图表片段；页面证据使用官方 `/projects` Web Demo 路由，不新增独立演示路由或页面 Story。真正的程序截图遵循逐次确认范围的既有规则。

推荐的 `150ms` hover 延迟、`500ms` 长按阈值、`8 CSS px` 抖动范围与 `48 CSS px` 触点避让范围是实现验证的起点，不作为新增产品决策逐项重复确认。验收以已确认的交互行为、完整数据表达、手指避让与原生滚动边界为准。
