# 按显示尺寸选择媒体水印

本文记录已确认的产品要求与本轮落地设计，供实现、静态发布和验收使用。它不表示功能已经上线，也不替代 [公开媒体 Spec](./specs/public-media-assets-facade/SPEC.md) 的长期合同；术语见 [领域术语](../GLOSSARY.md#公开媒体水印)。

## 已确认的需求

### 选择规则

采用已有 Iv 品牌标志：小图使用标志水印 A，大图使用署名水印 B；B 为 Iv 标志与 `ivanli.cc` 的横向组合。方案 C 不进入本次产品设计。

“大小”指图像在页面中实际呈现的可见宽度，以 CSS px 计量，不指原图分辨率、下载文件宽度、屏幕设备像素或物理毫米。同一显示宽度在普通屏和 Retina 屏使用同一种水印构图；设备像素密度只影响清晰度。

| 条件 | 结果 |
|---|---|
| 最终派生图宽度 `<240px`，或高度 `<160px`，或单帧面积 `<80,000px²` | 免水印 |
| 不属于极小派生图，且实测图像显示宽度 `<600 CSS px` | A：纯 Iv 标志 |
| 不属于极小派生图，且实测图像显示宽度 `≥600 CSS px` | B：Iv 标志 + `ivanli.cc` |

极小图判断先于 A/B 选择，判断对象是完成方向校正、缩放和取帧后的实际派生图尺寸，不是原图尺寸，也不是 CSS 显示尺寸。GIF 使用单帧高度和面积；视频封面使用实际生成帧的尺寸，不以配方中的 `height: 0` 判定。阈值是严格小于：例如 400×200 刚好达到面积门槛，不因面积免水印；240×160 虽达到宽高门槛，仍因面积不足而免水印。

同一图片可以在手机正文显示 A，在桌面正文或灯箱显示 B。横竖屏切换、阅读栏改变和灯箱打开后，应对各自显示位置重新选择；不能把“一张源图属于 A 或 B”写成媒体固有属性。

### 无法测量时的确定性输出

| 用途 | 默认构图 |
|---|---|
| 列表、时间线与相关推荐缩图（`card`） | A |
| 正文（`content`）、详情封面（`cover`）、大图查看（`full`） | B |
| 分享图（`social`）、独立视频封面（`poster`） | B |
| 视频播放（`play`） | 本次不对视频流叠加水印 |

RSS、分享抓取、禁用 JavaScript 的页面，以及浏览器首次测量前，按用途输出默认值；极小派生图仍优先免水印。正常网页测量后按 600 CSS px 分界校正，因此手机正文首次默认 B、随后换成 A 属于已接受的边界。不得承诺所有环境都能按照未知的最终显示尺寸选择。

### 适用范围

覆盖现有公开媒体门面中的文章和 Memo 图片、GIF 派生结果与视频封面，以及相同内容的作者态预览。站点图标、评论头像、装饰资源和 `/projects` 自有品牌资源沿用现有范围边界；本次不扩大到整段视频转码或视频播放器内的动态叠层。

水印烧录进派生文件，保存或转发该文件时仍保留。仅在页面上放一个 CSS/DOM Logo 不能满足此需求。公开性判断、管理员预览权限、metadata 清理、原始资源隔离和不放大派生图等既有约束继续适用。

## 项目实际显示情况

| 典型位置 | 代码推算的显示宽度 | 正常网页测量后的构图 |
|---|---:|---|
| 393px 视口的正文或 Memo 图片，图片撑满阅读栏时 | 约 361px | A |
| 同一移动视口的封面，图像撑满框宽时 | 最高约 393px | A |
| 宽屏双栏文章列表图 | 约 583px | A |
| 桌面正文图片，图片撑满阅读栏时 | 约 854px | B |
| 灯箱中的竖图或小原图 | 随图像宽高比与视口而变 | 按自身宽度选 A/B |

这些数值来自布局代码推导，不是截图实测值。原图不放大、竖图、`object-fit: contain` 和高度限制都可能使图像比容器窄；600px 是水印分界，不替代公共站现有的布局断点。

## 已定的视觉基线

两种构图都沿用 `site/assets/brand/source/ivan-blog-mark.svg` 的 Iv 轮廓，放在可见画面的右下角。采用白色主体、细暗色边线与 64% 整体不透明度，在浅底、暗底和复杂画面中验收；颜色不跟随页面主题切换，因为水印属于图片文件。

为避免把原型的 1200px 画布像素误当成屏幕尺寸，服务端以最终派生图宽度的比例定义视觉参数：A 宽 7%，B 组合宽 18%，右侧与底部留白各 2%。两者白色主体配细暗色边线，整体不透明度 64%；imagor 的 `alpha` 表示透明度，因此 filter 参数使用 `36`。这些参数是本轮实现和效果验收的视觉基线。

| 图像显示宽度 | 构图 | 水印显示宽度 | 基础边距 | B 的域名字号近似值 |
|---|---|---:|---:|---:|
| 361px | A | 25px | 7px | — |
| 583px | A | 41px | 12px | — |
| 600px | B | 108px | 12px | 14px |
| 854px | B | 154px | 17px | 20px |

比例由服务端在最终输出画布上实现，浏览器缩放后得到相应观感，不为每一个 CSS 宽度生成新文件。很窄的展示仍会使 A 随图片缩小；最终派生图低于极小图门槛时免水印，不通过客户端参数关闭水印。

B 的字形在资源版本内固定为同源 SVG 组合，避免服务端字体环境改变字宽；分隔线与主体同为白色，Logo 可见右缘到分隔线、分隔线到域名的间隔在 SVG 内固定一致。正式参数需通过真实布局中的浅色、暗色、复杂背景、竖图和超宽图验收；不采用逐图 AI 判断位置或自动识别主体。

B 方案中的 `ivanli.cc` 已转换为 SVG 路径轮廓，运行时不依赖字体文件或字体回退。

## 技术设计

### 前端测量与选择

前端统一使用一个媒体选择器，供 Astro 输出的列表与封面、React 正文媒体和灯箱调用。选择器接收媒体描述、用途与所在图像槽位，只选择后端提供的有限候选 URL，不拼接内部 source 地址。

用 `ResizeObserver` 监听图像槽位的布局尺寸变化，并在图片加载、路由进入、灯箱打开时计算图像实际可见矩形。该 API 可以观察元素的内容盒或边框盒变化；这里取扣除边框与内边距后的布局尺寸。[MDN ResizeObserver](https://developer.mozilla.org/en-US/docs/Web/API/ResizeObserver)

- `contain`：已知框为 `Bw×Bh`、校正方向后的图像为 `Iw×Ih` 时，缩放系数为 `min(Bw/Iw, Bh/Ih)`，图像显示宽度为 `Iw × 系数`。不允许放大的普通内联图还需受其实际布局尺寸约束。
- `contain`：当前列表、时间线、相关推荐、详情封面、正文和灯箱都在既有图框内完整显示，允许留白；分档宽度取 contain 后的可见矩形宽度。
- 宽度为零或元素隐藏时不进行校正，沿用用途默认值，显示后再测量。分界直接比较实际浮点宽度：599.9 用 A，600 用 B。
- 设备像素密度不参与 A/B 判断。它只能在已有清晰度候选中选择，不放大超过源图的有效分辨率。
- 以稳定布局尺寸判断，忽略 hover 的短暂缩放和双指临时放大；浏览器缩放导致 CSS 布局变化时重新测量。

本次只增加 A/B 展示候选，不额外增加按 DPR 改变输出尺寸的派生矩阵；同一用途使用相同输出尺寸，所以极小图豁免也不会随 DPR 改变。未来若增加低分辨率候选，必须同时满足“实际输出极小图免水印”和“同显示宽度的构图不受 DPR 影响”，不能直接让客户端在跨越豁免门槛的文件之间切换。

同一媒体的各候选需保持相同固有宽高比，预留稳定的尺寸空间；切换 URL 不能反过来改变槽位宽度并触发 A/B 循环。每帧合并测量，候选身份未变时不请求新文件，卸载与路由退出时释放观察器。首次默认图与校正图可能各请求一次，这是确定性初始输出的成本，不宣称零额外请求。

灯箱拥有独立测量和候选选择，打开时使用 `full` 派生，不再复用正文 `content` 的同一个 `src`。若手机灯箱中的图像仍不足 600px，它仍应使用 A。

### 派生和水印顺序

处理顺序为：读取与方向校正 → 用途所需的缩放/取帧 → 按最终单帧尺寸判断极小图 → 合成 A/B → 编码并清理 metadata。水印不能先烧到原图角落，再依赖页面 CSS 改变构图。

当前列表的媒体框保留原有几何尺寸，但图片改为 `object-contain`，允许主题协调的留白；图片自身的 hover 放大被移除。正文、详情封面与灯箱保持完整图像的 contain/自然比例。卡片外壳仍可保留整体 hover 阴影和抬升，不改变图片可见矩形。

contain 槽位须验证圆角、浅色/暗色背景和竖图留白；不再以图片自身放大后的裁切安全区作为水印合同。

### 服务端与资源身份

保留“前端选择、服务端烧录”的职责边界。现有 `card / cover / content / full / social / poster` 用途继续存在，每种用途只登记有限的 A/B、contain 和格式候选；免水印是尺寸规则的结果，不向访客提供任意关闭水印的参数。

渲染策略身份采用以下路径层级；只接受已登记的两个值，其他表达式一律 404。

```text
/api/public/assets/:kind/:slug/:mediaHash/:renderId/:variant.:ext

renderId = wm-a-v1 | wm-b-v1
           包含 A/B、contain 配方、Logo 素材指纹与合成参数
```

`mediaHash` 继续表示原有媒体身份，不用 A/B 重新计算媒体成员关系。`renderId` 只接受服务器登记的值，不是任意图片处理表达式。水印静态 SVG 自身也使用含素材指纹的同源路径，随 `site-dist` 发布，避免处理器回源缓存旧 SVG；现有 `/watermark-ivanli.svg` 保留为旧链接兼容资源。

结构化 `media` 增加可选的 `presentations`：非 `play` 用途提供 `{ a: URL, b: URL }`，每条使用该用途现有默认格式。现有 `variants`、`sources`、`poster` 与兼容字符串继续提供用途默认值；公开默认值为 `card -> A`、其他图片用途 -> `B`，`play` 保持受控播放。管理员预览默认继续使用旧 URL，同时接受显式版本化路径以保持旧快照兼容。

当前用途尺寸上限为 `card: 960×640`、`cover: 1600×900`、`content: 1440×不限高`、`full: 1920×不限高`、`social: 1200×630`、`poster: 1280×720`。它们不能代替显示宽度判断，也不因 A/B 变化而放大输出尺寸。

imagor 正常处理与 oversized 图片的本地 sharp 路径必须共用同一套水印策略和顺序，并用实际输出验证等价性。GIF 正文/大图继续保留动画，水印覆盖每帧；静态变体继续使用既有首帧语义。视频 A/B 派生在生成主 URL 前使用同配方的签名 `/meta` 读取实际 poster 尺寸。若尺寸探测或处理器失败，公开门面返回受控错误，不得返回无水印原图冒充成功结果。

### 静态发布与缓存

静态打包必须枚举正常网页可能选择的所有候选，包括初始 HTML 未直接使用的 A/B 和灯箱候选，再把每条 URL 改写成对应的 `/_content/assets/` 地址。运行时只能选择本次发布中存在的候选；候选会出现在结构化 `presentations`、HTML 属性和灯箱 `data-watermark-full-*` 属性中。

现有打包器的输出路径取自 pathname，查询串不参与文件命名。因此 `?watermark=a` 与 `?watermark=b` 会写进同一个文件，不能采用。渲染身份应进入路径，并体现在媒体 manifest 与静态文件名中，详见 [资源身份 ADR 提案](./adr/0025-display-selected-watermark-renditions.md)。

新策略不能只替换旧 SVG 或依赖 `?v=`：派生图有长缓存，打包下载去重按 pathname 区分候选。新发布必须同时切换候选描述、带渲染身份的新路径和静态文件，原有 snapshot 发布戳仍承担内容发布版本职责；不宣称旧缓存 URL 的字节会即时改变。对同一路径原文件的更新仍需现有内容发布失效机制覆盖，这不是 Logo 策略指纹能够单独解决的问题。

继续执行单文件 20 MiB、artifact 20,000 文件 / 5 GiB 的现有限制，并在发布前计算新增候选数量与体积。达到单文件阈值时按既有规则记录后端直连例外，地址仍要携带同一个渲染身份；候选缺失、下载失败或 artifact 超限均阻止发布，不在浏览器运行时退回原图。

### 兼容边界

已有旧路径保持解析兼容；新页面与新快照使用带渲染身份的 URL。旧路径可能仍返回或命中历史文字水印，不能作为新视觉已生效的证据。旧缓存保留、滚动发布顺序与回收窗口需记录在主题的 `IMPLEMENTATION.md`，不通过覆盖不可变对象实现迁移。

公开门面保持 fail-fast，管理员预览已有的授权原始媒体回退不因此扩展到匿名公开请求。后台编辑器原始素材与管理预览不得被打包进公开候选集合。

## 验收场景

| 编号 | 场景 | 应有结果 |
|---|---|---|
| WM-01 | 同一张高清图分别显示为 361px、583px、599.9px、600px、854px | 依次为 A、A、A、B、B |
| WM-02 | 同一图像显示宽度，DPR 分别为 1、2、3 | 构图一致，只允许清晰度不同 |
| WM-03 | 框宽 854px，但 contain 后竖图仅显示 450px 宽 | 使用 A |
| WM-04 | 正文显示宽 361px，灯箱显示宽 900px；关闭再打开 | 正文 A，灯箱 B，两个位置各自选择且无反复请求 |
| WM-05 | 最终派生图为 239×400、400×159、300×200、400×200 | 前三者免水印，最后一张按显示宽度选 A/B |
| WM-06 | 高清原图被缩放成极小派生图；另有相同 CSS 宽度的高清派生图 | 前者免水印；后者按显示宽度选 A/B |
| WM-07 | 多帧 GIF 或视频配方高度为 0 | 以实际单帧尺寸判断，动画行为符合原用途 |
| WM-08 | 列表、正文、分享抓取、禁用 JavaScript 和首次测量前 | 分别按用途提供 A/B 默认值；正常网页测量后校正 |
| WM-09 | contain 留白、圆角、浅色/暗色/复杂背景 | Logo 完整可见；B 在 600px 显示宽度时域名可辨 |
| WM-10 | imagor 正常结果与 oversized 本地派生结果 | 构图、极小图判断、位置和透明度符合同一策略，均无敏感 metadata |
| WM-11 | 同一媒体的 A/B 静态打包，并打开未预加载的灯箱 | 文件路径不同、无覆盖、所有候选可请求，manifest 可追溯 |
| WM-12 | 更换 Logo 或合成参数，再复用旧缓存并访问新发布 | 新 URL 与 SVG 指纹发生变化，新发布获取新水印；旧缓存不污染新身份 |
| WM-13 | 切换视口、隐藏后显示、快速开关灯箱或离开页面 | 布局稳定，无测量循环、重复监听和无界派生请求 |
| WM-14 | 私有/草稿媒体与异常派生请求 | 权限不放宽，公开请求不返回原图，发布不吞掉缺失候选 |

视觉验收应在正式组件或官方路由的 Web Demo 上完成，覆盖移动与桌面尺寸；既有 throwaway 画布只能说明构图方向，不能替代页面测量、contain 与发布链路验收。

```text
└─ 按图像显示宽度（CSS px）分档：已确认
   ├─ 小于 600 用 A，达到 600 用 B：已确认
   ├─ 无法测量时按用途默认，正常网页校正：已确认
   ├─ 极小派生图优先免水印：已确认
   └─ 落地方案：本文已定实现基线
      ├─ 服务端烧录，页面和灯箱独立选择
      ├─ 有限候选、版本化路径、静态候选闭包

```
