# 个人助手额度与全站 AI 统计采用不同用量范围

普通用户的助手额度用于约束其临时对话，而后台运营需要了解整个站点的 AI 消耗。因此，个人额度只核算本人助手问答及该轮检索实际触发的 AI 调用消耗；后台仪表盘与 AI 用量模块统计全站 AI 功能，包括对话、搜索、剪藏、标签整理等功能。

管理员产生的 AI 消耗同样计入运营统计，但不受个人额度限制。用量记录需要区分所属功能与可归属的用户，使个人额度核算与全站运营聚合各自采用明确的范围。

普通用户采用滚动额度窗口，默认最近一小时最多消耗 10M Token、最近七天最多消耗 100M Token，后台可调整这两个上限。旧消耗移出窗口后额度逐步恢复，前台显示剩余额度与下次恢复时间。

额度上限由后台全局统一配置，不支持单用户自定义上限。管理员可以对单个用户执行配额恢复，同时将小时与七天两档 Token 和问答次数可用额度恢复至全额；用户列表、运营统计和真实用量历史均不清零，操作只影响该用户可继续使用的额度。

用户维度的 Token 用量按实际输入与输出合计核算：输入包括系统提示、历史对话、检索材料及缓存命中的输入；输出包含回答与模型思考消耗，按提供方用量口径计入并避免重复累计。取消、失败或重试已经产生的实际消耗也计入，用户用量分别展示输入、输出及总量；该加总规则仅适用于用户维度，不据此确定全站运营统计的指标口径。

请求失败或中断而无法取得完整用量时，允许以保守估算占用个人额度并标记为估算，取得实际用量后再校正。运营原始用量继续标记为缺失或不完整，估算值单独保留。

个人助手使用除 Token 额度外，还受到问答次数限制。每条用户消息开始处理后计一次，用户主动重试另计一次；内部检索、多步处理及自动重试不额外扣次数，运营统计仍记录每一次实际模型调用。

普通用户问答次数采用滚动窗口，默认最近一小时最多六十次、最近七天最多三百次，后台全局统一配置；管理员不受问答次数上限限制。

运营维度保留提供方的原始分项用量，包括输入、缓存命中、输出、思考 Token 等字段，注明字段的包含关系并避免重复累计。同时展示调用次数及成功、失败、中止情况，支持按功能、模型和时间范围聚合。

调用明细保留九十天，按用户、功能、模型形成的每日汇总长期保留，用于长期趋势与累计消耗统计。用量记录不额外复制提示词或回答正文；对话删除、过期和单用户配额恢复均不清除真实用量统计。
