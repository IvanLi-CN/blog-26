# 两种 AI 搜索独立执行，直接回退关键词全文搜索

公开搜索出现真实命中被语义候选遗漏、无关输入仍返回大量内容并显示高相关度的问题。搜索提供可手动选择的 RAG、查询改写和关键词三种模式，均返回实际内容列表；两种 AI 模式独立执行，不互相接管失败，任一不可用时以原始查询直接回退关键词。

RAG 让 LLM 阅读检索候选、判断相关性并排序；查询改写让 LLM 只理解查询，再由全文引擎执行和排序，模型不读取站内目录或检索反馈。两者可以共享底层引擎及提供方，但不共享执行链、质量结论或故障状态。这接受两种模式发现能力不同，保留明确比较与独立使用的边界。

两种 AI 模式都保全原始查询的合法关键词容量，再统一排序有效补充；模型可以改变顺序，不能删除文字命中。明确语法直接执行关键词。配置、调用或质量策略不可用时只返回原始关键词；正常空结果不换模式。回退保留用户的模式选择并如实说明实际执行模式，内部排序值不展示为相关度百分比。

公开 HTTP、tRPC 与 MCP 采用相同规则，保留 enhanced 兼容入口及显式底层 semantic 检索。名称边界和确定别名不依赖 AI；中文保留连续片段匹配。搜索 Node 的真实命中不能因模型推测语境被删除；搜索 NodeJS/Node.js 扩展到只有 Node 的内容需要 RAG 判断运行时上下文，查询改写不能用无条件生成 Node 绕过该限制。

默认模式为 RAG，显式模式选择优先。该默认值及结果排序决策已由 [ADR 0022](./0022-keyword-default-unified-ranking.md) 取代。全文索引、检索与排名交给成熟引擎；项目负责受控查询适配、权限、内容同步及三种模式编排，不自行实现倒排索引或通用分词。采用内嵌 Tantivy 的理由、原生接入成本及 NEAR 兼容范围见 [ADR 0021](./0021-embedded-tantivy-search.md)。

长期要求与验收边界见 [搜索相关性契约](../specs/search-relevance/SPEC.md)。
