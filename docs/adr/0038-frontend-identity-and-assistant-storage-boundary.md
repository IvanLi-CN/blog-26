# 前台身份与助手应用存储保持独立边界

站内知识助手使用应用自有的 SQLite 表保存前台身份、对话、消息、生成任务、用量、每日汇总、配额策略和迁移状态。既有 Pi 剪藏运行时继续负责剪藏处理，不作为新助手消息的所有者；`memo_clippings.conversation_id` 也不在本次迁移中改写。这样可以让统一对话列表、私人消息归属和生成恢复拥有稳定的应用数据边界。

前台身份使用独立的、有效期七天的哈希会话。可信管理员账号和 GitHub 读者身份通过显式身份链接归属于 `frontend_users`；已确认的管理员 GitHub 绑定可以指向同一前台用户，但不作为管理员首次获得前台身份的前提。后台 `session_id` 和 GitHub `reader_session_id` 只用于建立或更新入口，不参与已建立前台会话的每次读取，因此后台会话过期不会直接使前台对话失效。

显式前台退出会撤销前台会话并设置短期抑制标记。后续 bootstrap 在标记存在时不自动从后台或读者会话重新登录；管理员必须通过显式 `admin-start` 入口重新建立前台会话。该边界避免退出后因后台仍然有效而立即登录回环。

本次迁移只执行 DDL：新增表、索引和评论的可空统一归属字段，旧评论的 `readerId`、作者字段和剪藏运行时结构保持兼容。历史剪藏讨论归属、消息转换及无法确认记录的隔离由后续可观察、可暂停的独立 backfill 任务负责，不在结构迁移中猜测作者或删除记录。
