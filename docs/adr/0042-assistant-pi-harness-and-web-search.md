# 助手统一使用 Pi Harness 编排模型与工具

## Decision

一般助手与剪藏对话的模型执行统一复用 `@earendil-works/pi-durable` Harness 和 `@earendil-works/pi-ai` provider adapter。应用层继续拥有前台身份、对话历史、generation job、租约、取消、消息快照、引用和配额；Pi 负责模型请求、工具调用循环、上下文压缩及逐次 provider 计量。此决定细化 ADR 0038 的执行边界，不改变其应用存储所有权。

一般助手每个 generation job 创建隔离的内存 Pi 会话，从应用历史恢复带角色的模型上下文，结束后关闭。Pi 不建立另一份持久化私人消息库；服务重启仍按既有任务契约将中断生成标记失败，刷新或路由切换则继续读取应用任务。剪藏后台处理继续使用既有持久化 Pi runtime；剪藏对话使用相同 Pi adapter，但维持当前文章上下文与禁止联网的契约。

一般助手支持通用回答，并通过 `site_search` 按需优先查证站内事实；稳定常识不强制检索。时效性、明确联网或不确定事实通过 `web_search` 调用配置的 Tavily Hikari HTTP API。默认每轮最多十二次联网搜索，可由服务端配置调高；同时存在整体十分钟执行期限、provider 请求保险上限、逐次超时和显式取消。搜索错误作为可理解的工具结果返回，允许模型说明限制并完成可靠部分。

外部引用使用独立的 `web` 来源身份，仅接纳真实工具返回且 URL 协议有效的结果。Tavily Token 只由服务端环境读取，使用 Bearer Header，不向模型、浏览器、日志或仓库写入；禁用自动 HTTP 重定向。

## Privacy and cost

站内检索继续按调用者身份授权。管理员历史可能含非公开站内内容，因此管理员联网工具只发送当前用户问题，不发送模型生成的查询；普通读者的工具可以按公开主题改写查询。该保守策略牺牲管理员联网查询的改写自由，以避免模型将私有材料经搜索词导出。所有上下文材料仍是非可信阅读数据，不获得指令权限。

模型多次请求复用同一 logical question，逐次记录真实 provider 消耗；Tavily 搜索单独记录 `assistant-web-search` 事件与调用次数，不伪装为模型 Token。Tavily 缺少凭据时保留通用回答能力，并向模型明确工具不可用。

## Alternatives

继续扩展自研 Chat Completions 循环需要重复实现工具调度、provider 适配和上下文压缩，且会继续形成两套运行机制。把私人消息完全迁移到 Pi 存储则引入额外的消息归属、到期删除、历史迁移与恢复语义变更。保留应用存储并统一执行引擎可以复用既有契约，代价是每轮需要恢复 Pi 模型上下文，工具过程不跨进程恢复。
