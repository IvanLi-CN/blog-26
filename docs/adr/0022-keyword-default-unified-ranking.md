# 关键词默认与混合结果统一排序

## Context

搜索需要先快速返回可靠的全文命中，同时允许 RAG 或查询改写补充语义相关内容。将所有 AI 结果固定追加到列表末尾，会把相关性更高的补充内容排在较弱的文字命中之后；默认启用 AI 也会让基础搜索依赖模型可用性。

## Decision

页面未指定模式时使用 `keyword` 全文检索，也就是智能搜索控件的“关闭”状态。选择 `rag` 或 `rewrite` 时，先取得用户原始查询的合法关键词集合，再取得经过对应链路确认的补充候选；两者使用同一相关性排序输出。关键词命中受保护：在返回上限内不得被删除或被补充结果挤掉；当候选超过上限时，补充只能参与排序和截断，不得引入范围外内容。AI 失败、超时、未配置或未通过质量验证时，直接返回原始关键词结果。

前端可以延迟展示 AI 补充以表达加载过程，但补齐时必须保留服务端已经决定的统一顺序，不得按来源重新分组。AI 补充仅通过卡片标记识别，不展示不可解释的百分比。

## Consequences

基础查询不依赖 AI，首屏响应稳定；高相关的语义补充可以插入关键词结果之间。实现需要在候选合并时保护原始命中，并为 RAG、查询改写和回退分别验证排序与容量边界。

内嵌 Tantivy 的引擎职责和 NEAR 兼容范围仍由 [ADR 0021](./0021-embedded-tantivy-search.md) 定义。
