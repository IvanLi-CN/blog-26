# 统一搜索排序与独立 Playbook 同步管理

> Playbook 动态来源和静态指针跟随部分已由 [ADR 0030](./0030-github-source-and-database-playbook-snapshots.md) 取代；本 ADR 的统一搜索、内容聚合、原子词法投影和 RAG 独立性仍然有效，具体来源边界以当前主题 Spec 为准。

搜索页在浏览器中拼接文章/Memo 与 Playbook 的结果，使程序化入口缺少 Playbook，也使“全部”无法按相关性综合排序。Playbook 的后台更新虽已存在，却没有进入管理员的内容同步视图。决定由共同的服务端检索边界提供跨来源搜索、聚合、筛选和综合排序，并把 Playbook 作为独立来源纳入内容同步管理；统一检索与管理不合并内容所有权或发布流程。

## Considered Options

- 继续浏览器拼接独立排名：成本较低，但不同入口无法提供同一结果语义，“全部”仍按来源顺序占据位置，筛选会被先前截断的结果范围限制。
- 将 Playbook 写成文章/Memo：可以直接复用现有投影，但会混淆内容身份、授权、数量统计和版本切换，也使本地全量同步可能误删外部内容。
- 控制台直接跟随上游仓库或在页面请求时取内容：可以更早获得更新，但需要运行时凭据并破坏两站跟随已发布快照的边界。

## Consequences

“全部”对合格的独立内容综合排序并使用一个返回上限；来源与类型筛选先于内容截断，章节和资源文件不增加顶层内容数。不得直接比较不同引擎的原始分数、对每批最高分分别拉伸后比较，或用固定交替代替相关性排序。搜索排序投影可以统一，但内容来源、公开性和持久数据责任保持独立；具体投影和评分实现必须证明共同相关性语义。

Playbook 在关键词和现代 RAG 模式中参与原始查询的确定性检索；查询改写仍只处理文章/Memo，不读取或改写 Playbook。现代 RAG 可以判断同一公开 edition 的 Playbook 候选，资源正文以不可信证据分隔传入，模型只能返回候选 ID、相关性、排名和证据。AI 故障不会删除 Playbook 命中，统一服务需要显式隔离候选范围、edition 身份和模型输入边界。

Playbook 搜索包括已发布公开包中的 Topic、项目实践、Policy Skill 指令与附带公开文本文件。资源命中归入所属 Policy Skill，并定位到同一快照中的文件。网页和程序化调用在请求开始时使用控制台当前采用快照；旧搜索 URL/API 携带的版本字段只为兼容接收并忽略，不能选择版本或触发冲突。响应仍可报告实际快照 provenance，阅读/资源路由及内部语义投影继续绑定完整 edition。现有独立 semantic 和历史 enhanced 参数保留兼容意义。

管理员统一查看和触发各来源同步，Playbook 仍只跟随博客成功部署的公开指针。手动入口检查并采用该指针，不选择任意 Release、不触发生产发布或回滚；私有源凭据留在 CI。目录、正文、资源和词法搜索投影通过校验后在一个原子点采用；语义投影按同一 edition 异步准备，不是内容采用的前置条件。语义投影缺失、失败或取消时保留已采用内容，并在状态与搜索元信息中报告 pending/failed 或覆盖不足；下载校验失败或在采用前取消时保留旧版本。同步暂停与已有内容是否可读分开表示。生产发布、显式回滚及应用版本的边界继续由 [ADR 0011](./0011-published-playbook-read-model.md) 定义。

长期需求分别由 [搜索契约](../specs/search-relevance/SPEC.md) 和 [Playbook 集成契约](../specs/style-playbook-integration/SPEC.md) 拥有。
