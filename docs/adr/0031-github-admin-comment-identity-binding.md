# 显式绑定 GitHub 身份用于管理员评论作者识别

GitHub 读者登录与管理员授权必须继续隔离，但前台需要一种可信方式识别管理员发表的公开评论。仅凭 `ADMIN_EMAIL`、评论邮箱、GitHub login、昵称或其他公开资料自动匹配都会把可变或未经确认的资料当作权限边界，既无法处理冲突，也无法稳定保留历史归属。

## Decision

- 现有唯一管理员账号最多绑定一个 GitHub 永久用户 ID；一个 GitHub 用户 ID 不得绑定到其他管理员账号。绑定关系只由已认证管理员在后台发起，并通过服务端 GitHub OAuth 授权码、一次性 state、PKCE S256、合法回跳和明确确认建立或解除。
- 绑定使用现有 GitHub OAuth App 的最小公开身份资料范围，不申请仓库或私有邮箱权限。冲突、错误账号、失败、过期和重放都拒绝变更并保留旧关系；绑定、解绑、冲突和失败记录管理员账号、GitHub 用户 ID、动作、时间和结果，但不记录 OAuth token。
- 绑定后的 GitHub 会话仍然是读者会话。它只允许在公开目标发表带持久化管理员作者标记的主评论或合法回复；后台、审核、编辑、删除他人、恢复和私有内容仍要求既有管理员会话。管理员会话单独不能伪造管理员评论作者。
- 管理员主评论和回复直接以已通过状态公开，并在作者资料旁显示统一的“管理员”标记；它们仍遵守评论对象、输入、幂等、缓存隔离和频率限制。普通读者评论继续走待审核流程。
- 解绑只影响后续新评论。已有管理员评论保留作者标记、审核状态、正文、回复关系和公开性；已有 GitHub reader 会话继续有效，重新绑定必须重新完成 OAuth。GitHub 资料可按稳定用户 ID 刷新，但资料变化不改变绑定或评论归属。

## Consequences

管理员可以在前台以可验证且稳定的作者身份发言，同时不会把 GitHub 登录升级为后台权限。实现需要新增绑定关系、作者属性快照和审计记录，并在评论创建、公开投影、恢复、解绑和缓存隔离路径中保持一致；历史评论不因绑定而自动获得管理员标记。

本决定取代 [ADR 0029](./0029-github-reader-and-legacy-comment-identity.md) 关于“GitHub 身份与管理员评论作者完全隔离”的边界，但保留其历史评论不自动认领、不按邮箱或昵称合并的迁移保护。
