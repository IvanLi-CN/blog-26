# 产品预发布的发布与部署边界

统一产品发布支持正式版及 alpha、beta、rc 产品预发布。所有渠道的发布集合均为静态前台归档和完整功能 Docker 镜像；两种产物共享产品版本和确切来源。产品预发布是具有预发布版本标识的产品交付，部署目的地是独立概念。

alpha、beta、rc 发布两种产物，不部署静态站点，不推进正式版 GitHub Release latest、镜像 latest 或生产内容指针。GitHub 将预发布标记为 prerelease；静态归档和镜像使用可追溯的版本身份。该边界使预发布能提供真实的产物交付证据，同时不要求增加预览站点或改变正式站点。

手动入口保持唯一可选文本输入 `version`。留空或 `stable` 请求自动正式发布；`alpha`、`beta`、`rc` 请求对应阶段的自动版本分配；完整产品版本请求经过语义与向前校验后按指定值发布。渠道由解析后的产品版本确定，不增加 `channel` 或 `target` 输入。文本输入同时支持快捷请求和完整指定，避免把 GitHub 原生预设下拉框的选择范围变成产品版本限制。

快捷请求是发版人的输入意图，不能直接成为 VERSION、tag 或产物中的版本。系统必须先解析请求并分配完整 SemVer 产品版本，再建立不可变发布身份和预留；失败重跑沿用原请求及已分配版本，不能重新分配序号。

真实预发布验收须证明机器人 VERSION-only PR、受保护自动合并、确切 merge SHA 的质量门禁及两种不可变产物发布成功；候选 CI 或本地构建通过不能代替这些证据。正式发布仍按原合同部署已验证的静态归档并验证生产来源；预发布成功不证明正式站点部署已经验收。

本决定约束版本请求和产品预发布的发布与部署边界；自动分配的目标递进、阶段回退及正式版转换规则由版本策略合同定义。既有产品发布单元见 [ADR 0014](./0014-unified-product-release-version-scope.md)，手动交付边界见 [ADR 0015](./0015-manual-version-release-delivery.md)，正式发布的冻结产物与生产指针约束见 [ADR 0016](./0016-signed-release-ledger-and-frozen-products.md)。
