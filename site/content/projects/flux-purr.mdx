## 项目介绍

Flux Purr 为嵌入式设备提供一套完整的软件控制面。固件运行在 ESP32-S3 上，Web 控制台负责设备操作和状态展示，CLI 与 `flux-purr-devd` 负责本地设备访问和维护。

项目的重点是统一设备协议和操作路径。设备身份、能力、连接方式、运行状态和错误信息由同一套模型表达，因此 Web、CLI 和本地守护进程可以使用相同的设备语义。

</section>

<section className="project-mdx-section">

## 架构

系统分为三层：

- 固件层：负责温度采样、PID 加热、PD 状态、风扇、前面板和 EEPROM 配置。
- 本地设备层：`flux-purr-devd` 负责 USB/串口发现、独占 lease、有限 monitor 事件和 Wi-Fi 配置桥接；`flux-purr` CLI 通过 native IPC 使用这些能力。
- 控制台层：React Web App 通过 Web Serial、devd 或局域网 HTTP 连接设备，展示设备状态并执行允许的操作。

<ProjectArchitectureDiagram />

Web 控制台不直接承担所有本地设备操作。首次 Wi-Fi 配置、固件烧录和配对令牌重置必须使用 USB 路径；完成配置和配对后，设备才可以通过可信局域网 HTTP 进行日常控制。

</section>

## 功能概要

控制台支持以下功能：

- 发现设备并显示设备身份、连接方式和设备能力。
- 查看温度、输入输出状态、PD contract、加热和风扇状态。
- 配置 Wi-Fi，并通过局域网控制已配对设备。
- 执行 VIN ADC、RTD 温度和加热曲线校准。
- 检查固件产物，并执行普通更新或开发者烧录。
- 查看设备监视事件和诊断信息。

控制台会区分 `live`、`mock`、`offline`、`degraded`、`pending` 和 `unsupported` 状态。动作只有在设备能力和安全条件满足时才会开放。

**热控与安全行为**

固件使用 RTD 采样和 PID 控制加热输出，并根据 PD contract 判断当前电源条件。PD contract 未就绪、传感器故障或发生绝对过温时，加热输出保持关闭；控制台仍然可以显示状态和故障原因。

软件功率限制用于约束控制逻辑，不能替代硬件过流保护。当前硬件基线使用 ESP32-S3，具体电源链、PD 芯片和风扇电路以 `docs/hardware/` 中的资料为准。

</section>

<section className="project-mdx-section">

**校准数据**

校准分为三个阶段：采集样本、生成拟合建议、写入生效参数。

样本和拟合建议不会自动改变设备运行参数。只有将结果写入指定的 A/B 参数槽位并完成设备确认后，运行时才会使用新参数。设备身份不匹配、参数不完整或运行条件不满足时，流程会停在诊断状态。

</section>

<section className="project-mdx-section">

**固件维护**

普通用户使用本地 `.fluxpurr-fw` bundle 更新固件，bundle 必须通过发布清单中的 SHA-256 校验。开发者可以使用指定串口和本地 ELF 执行 `flash`；该流程默认备份 EEPROM。`recover` 用于明确确认后的 MCU 内部 Flash 擦除，不会修改外部 EEPROM。

每次固件操作都要求明确的串口。CLI 不会自动扫描、选择或记忆物理设备。

</section>

## DIY 使用路径

1. 通过 USB 连接设备并确认串口和设备身份。
2. 烧录或更新匹配的固件。
3. 通过 USB 配置 Wi-Fi 和配对信息。
4. 使用 Web 控制台查看状态和执行日常控制。
5. 在满足 PD、温度和设备能力条件后执行校准。
6. 使用 monitor、日志和状态信息排查问题。

公共 Demo 只模拟设备状态和控制台交互，不执行真实烧录、凭据写入或配对重置。
