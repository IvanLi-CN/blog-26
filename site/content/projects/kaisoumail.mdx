## 把一次性邮箱做成可操作的控制面

KaisouMail 面向需要管理临时邮箱、接入自有域名并查看邮件内容的场景。它不是一个只展示收件箱的页面，而是把邮箱生命周期、域名接入、邮件阅读、验证码提取和自动化凭据放到同一个 Cloudflare 原生控制面中。

项目将 Web 控制面、API Worker、邮件接收 Worker 与 Cloudflare 的存储能力组合起来，让自托管实例可以在不依赖独立邮件服务器的情况下完成从域名到消息阅读的完整链路。

## 从入站路由到可读消息

入站邮件首先经过 Cloudflare Email Routing，再由 Email Worker 接收。Worker 将结构化元数据写入 D1，将原始邮件正文和相关内容放入 R2；控制面通过 API Worker 读取这些状态，React 界面则负责邮箱列表、消息列表和正文阅读。

这种拆分把“邮件事实”和“控制面状态”分开保存：D1 适合查询和筛选，R2 保留正文与原始消息，Pages Proxy 让前端继续使用同源 `/api`。当验证码提取无法仅靠确定性规则判断时，Worker 可以调用 Workers AI 作为歧义处理路径，而不是让所有消息都依赖模型。

## 邮箱地址有自己的生命周期

邮箱创建支持随机分配，也支持输入具体地址；邮箱记录同时保存创建来源和标签，便于在多个自动化流程之间筛选和回溯。TTL 从 1 小时到 1 年覆盖短期验证场景，也可以选择长期有效模式。

工作区只聚焦当前可处理的数据：`active` 和 `destroying` 邮箱进入工作区，其他历史状态不混入日常操作列表。这样的边界让邮箱列表保持紧凑，也避免历史记录撑长操作面。

## 域名接入从 apex 开始

`/domains` 页面负责发现可管理的 Cloudflare zone、启用目录中的域名或直接绑定新的 apex 根域名。项目将 apex 绑定作为标准 onboarding 路径，需要子域名地址时，再在根域名已经接入的基础上继续创建。

Catch All 的启用和禁用会创建异步 cutover task，项目清理或重建自己管理的 Email Routing 记录，并通过任务 API 和 SSE 提供可追踪的进度。长时间的 DNS 协调因此不会被压缩成一个无法解释的 loading 状态。

## 阅读、验证与自动化入口并列存在

消息详情可以查看解析内容、HTML、纯文本、headers、收件人、附件以及原始 EML。对需要脚本化操作的场景，API Key 库和受保护的 API 参考文档位于同一套身份认证区域；Passkey 则负责浏览器登录和设备管理。

KaisouMail 同时保留公开文档站、部署说明、Cloudflare 权限指南和 Storybook 预览。首次了解项目时可以使用 mock data Demo，不必先准备 Worker、Cloudflare 账户或真实邮箱域名。
